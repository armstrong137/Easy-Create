# 魔树 img2img 链式生成配方

## 目标

生成 `picture/魔树动画素材` 下的 28 张高清 JPEG：

`magic_tree_f01.jpg` 到 `magic_tree_f28.jpg`

正确语义是：**完整小树苗自然长成完整魔藤树**。每一帧都必须是完整植株，有土堆、有主干、有树冠，不能是成熟大树的一部分。

## 已否决路线

1. 禁止把一张成熟大树等比缩放成 28 档。
2. 禁止把一株成熟大树自下而上揭开。
3. 禁止切片平铺、纵向拉伸、镜像翻转、羽化拼接。
4. 禁止用后期覆盖层、涂抹、平涂色块、贴图补树冠。

## 固定规格

| 项 | 要求 |
|---|---|
| 数量 | 28 帧 |
| 尺寸 | 941 x 1672 |
| 格式 | JPEG q90 |
| 背景 | 固定 `#FDF6EC` |
| 文件名 | `magic_tree_f01.jpg` ... `magic_tree_f28.jpg` |
| 土堆 | 位置、宽度、底边、纹理逐帧固定 |
| 机位 | 完全固定，不能推拉平移 |
| 光照 | 完全一致 |

## 生长语义

- f01 是完整小树苗：细主干、少量叶片、闭合小树冠。
- 中间帧逐步长高、主藤变粗、叶片数量增加。
- 单叶绝对尺寸基本稳定，不能跟着整株同比例放大。
- 每一帧顶端都要是真实绿色生长点：卷曲嫩梢加 1 到 2 片小嫩叶。
- f28 是完整成熟魔藤树。

## 链式生成建议

优先使用 img2img 链式生成：

1. 先人工确认 f01 小树苗质量。
2. f02 以 f01 为输入，低重绘强度，只允许“长高一点、多一两片叶、主藤略粗”。
3. f03 以 f02 为输入，依次类推直到 f28。
4. 每生成 4 到 6 帧跑一次 validator，发现土堆漂移或背景漂移立即回退。

推荐重绘强度：

| 区间 | denoise |
|---|---|
| f01 | 0.34 左右，用于生成/整理初始小树苗 |
| f02-f05 | 0.16 |
| f06-f18 | 0.14 |
| f19-f28 | 0.12 |

如果生长幅度太小，只微调到 0.18 到 0.20；如果土堆或背景开始漂，降低强度，并用 mask/control 锁住土堆与背景。

## 脚本用法

写出配方：

```powershell
python scripts/magic_tree_img2img_pipeline.py write-recipe --out "picture\魔树动画素材\magic_tree_img2img_recipe.json" --reference "picture\魔树动画素材\approved_highres_reference.png"
```

接外部生成器 dry run：

```powershell
python scripts/magic_tree_img2img_pipeline.py run --recipe "picture\魔树动画素材\magic_tree_img2img_recipe.json" --provider-command '你的生成器命令 --input "$input" --output "$output" --prompt "$prompt" --negative "$negative_prompt" --denoise $denoise --width $width --height $height --seed $seed' --dry-run
```

PowerShell 里模板必须用单引号包住，否则 `$input`、`$prompt` 等占位符会被 PowerShell 提前展开成空值。

### Stable Diffusion WebUI / Forge provider

本仓库已提供 `scripts/magic_tree_sd_webui_provider.py`，用于把单帧参数转成 WebUI / Forge 的 `/sdapi/v1/img2img` 请求。使用前先启动后端并开启 API，例如：

```powershell
webui-user.bat --api
```

若 API 地址不是默认的 `http://127.0.0.1:7860`，先设置：

```powershell
$env:SD_WEBUI_URL = "http://127.0.0.1:7860"
```

正式生成：

```powershell
python scripts/magic_tree_img2img_pipeline.py run --recipe "picture\魔树动画素材\magic_tree_img2img_recipe.json" --provider-command 'python scripts/magic_tree_sd_webui_provider.py --input "$input" --output "$output" --denoise $denoise --width $width --height $height --seed $seed' --json-out "picture\魔树动画素材\validation_report.json"
```

这个 provider 会从 pipeline 设置的 `MAGIC_TREE_PROMPT` / `MAGIC_TREE_NEGATIVE_PROMPT` 环境变量读取提示词，避免超长中英文 prompt 在 PowerShell 命令行里被错误拆分；同时会把配方里的 `denoise_strength` 原样传给后端的 `denoising_strength`。如果后端没有启动，脚本会直接失败，不会静默生成错误素材。

验收：

```powershell
python scripts/magic_tree_img2img_pipeline.py validate --frame-dir "picture\魔树动画素材" --json-out "picture\魔树动画素材\validation_report.json"
```

## 当前有效硬判据

`not_reveal_sequence` 是区分“完整植株生长”和“成熟大树揭开”的关键硬判据：

第 k 帧与 f28 在第 k 帧植株顶以下重叠区的平均像素差必须 `>= 20`。低于该值说明第 k 帧本质上就是成熟大树下半截。

`crown_green_coverage` 只保留为诊断项，不再作为通过条件。原因：揭开式切口如果刚好切在绿叶中间，也会让顶端 15% 区域有足够绿色，但这不代表它有真实树冠。

## 人工复核

validator 只能挡住整体路线错误。最终仍需按真实 App 显示尺寸检查：

1. f01 是否是一株完整小树苗，而不是成熟树缩小版。
2. f06、f10、f14、f18 是否都有自然树冠。
3. 相邻帧是否像“长了一点”，而不是换树、推镜头或揭开。
4. 土堆是否完全不动。
5. 树冠是否没有灰烟、亮边、平涂补丁。
