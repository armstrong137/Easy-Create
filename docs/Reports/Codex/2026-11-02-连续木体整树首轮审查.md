# 连续木体与横展冠层首轮：四图短片完成，视觉未通过

本轮从局部插画两轮失败结论出发，重新制作一个连续的根脚—根颈—主干—五条主肩枝源片，以及横展冠层枝叶，不再通过通用Y分叉与独立根盘堆叠整树。新的完整候选已在实际Flutter二维入口交付幼苗、中龄、成熟、枝牌近景及连续成长短片。**首套仍视觉拒绝，A2未通过，不进入集成。** 这是专门制作的一体主木体资产方案第一套完整审查，旧四条路线的两轮淘汰决定继续有效。

## 新方案实际改变了什么

内置image_gen按imagegen技能生成continuous_wood_core_v1.png和canopy_boughs_v1.png。前者包含连续根颈和五条短主肩枝，没有叶冠与外围枝；后者包含左/右横展枝、上层冠、幼芽枝四件局部元素，没有树干、根或UI。提示词、原输出名称、用途和SHA256均在源图同名.md与.prompt.txt中。保留原透明PNG，不覆盖旧资产，未引入第三方素材。

continuous_core_proof.py对主木体使用一次固定UV映射，根颈不再是独立前景覆盖片；按实际解剖点制作25个核心节点、24条核心骨边，主干高度、肩枝伸展、增粗及根幅分别控制。12个局部枝叶和两侧木牌共用所属真实节点，使用四张原始纹理；牌面仍由同帧框角绘制。底层主木体没有完整叶冠，不是把一张成年整树拉长或等比缩放；没有整树阶段图片、动画帧贴图或材质随树龄换图。

幼龄到成年使用同一图像和同一网格UV，通过骨长/径向控制形变。幼木对比度通过按纹理类型的连续色彩矩阵调整，叶片和框材质分别调色。当前幼态矩阵过平，是本轮问题，不能以此证明年轻树皮已自然。

只读透明分析确认冠层源图并非严格四等分，底部拱冠跨越名义中线；按四个真实连通区域生成网格，未改PNG像素。独立.blend保存网格/UV编辑快照，成长控制源为脚本与导出节点/姿态数据，不宣称该快照已经有可直接发布的Blender骨骼动画工程。

## 整套视觉审查：拒绝

| 对照项 | 实际画面 | 下一套整体修改条件 |
|---|---|---|
| 干根连续性 | 首轮原有横向根颈覆盖缝消失，木体由根脚延续进主分叉；近景可读 | 保留连续源体，继续检查根脚接地和形变，不恢复独立根盘遮挡 |
| 成熟比例 | 冠层能横展，但整树过于矮宽，接近盆景灌丛；根幅、干高和冠层关系偏离批准参考 | 重新安排主次枝的实际局部长度、角度和冠层挂点，不能用相机缩小或横向挤压整树掩盖比例 |
| 叶冠层级 | 不再是重复竖柱，主肩枝与横展叶枝有自然体积；横层仍规则，部分叶枝粗度/密度重复 | 调整冠层大体块与间隙、叶枝尺度和次级支撑，减少相等台阶，避免单纯增加叶数 |
| 幼苗及中龄 | 根、干、叶完整，但幼苗细干与根幅失衡，像细线接三角根脚；调色使木体过平，早中龄肩枝展开规则 | 重做局部幼龄骨架比例、幼根姿态及材质对比度，协调展叶与侧枝发育；不能放大整棵成年树或换阶段图 |
| 枝牌 | 左章右节、成熟可读、不透明纸面展开；承托枝接在真实主节点 | 木牌偏暖，树体偏灰绿；粗重框体、母枝连接和整体细节密度需共同统一 |
| 构图 | 全景木体与冠层未裁切，近景两牌可见；实际手机视口尚非页面验收 | 冠干比例修正后重新拟合固定相机并复查，不能把宽留白当最终阅读布局 |

实际查看了四图和成长源帧025/075，完整短片与手机视口随证据保存。新连续源体确实改变了根颈接合方式，但不能抵消比例、幼态和冠层问题。当前是第一轮整套失败，剩一次整体修改；若第二套仍整体失败，则停止该完整方案，不以局部改动、代码改名或性能改善重置轮次。
