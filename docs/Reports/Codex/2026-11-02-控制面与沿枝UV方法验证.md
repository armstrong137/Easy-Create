# 控制面与沿枝UV：资产方法验证

本轮实际改换资产制作方式：用明确的控制面开口和共享顶点桥接根系、母干与两处子枝，UV按解剖部位定义连续条带。不使用球/锥体并集、体素重网格、自动简化分图或旧Blender母版。它验证新的连接与材质方法，**不包含叶冠或枝牌，不是完整树苗/成熟整树，不代表A2通过**。

## 当前可复查的资产

新源脚本tools/tree_scene/rectification/authored_surface_proof.py独立新建场景。576个控制顶点、538个控制面，保留可编辑母干截面、六处根系和两处母子分叉。母干上2×2控制面开口的八点边界与子枝第一圈直接共用顶点，没有交叠母干外壳掩盖接头。细分后8898顶点、17792三角形，一个连通分量、零非流形边。

初次结构检查发现开口中央有八个不再属于任何面的控制点，生成阶段已通过明确的面引用列表排除未使用点；没有删除断开的实体来伪造连通。原检查日志另存。线框图显示实际控制笼和接头，源快照保留控制面及细分修改器，可由脚本约数秒重建；它是新场景，不覆盖旧母版。

材质直接使用已有1024树皮图，沿枝长条带重复采样，无需烘焙一张大图集。实验加载接口沿用baked-bark.png文件名，但内容是原始材质副本，不能称为烘焙结果。源UV与原始纹理哈希可追溯。

局部控制骨架定义三个姿态，分别改变主干、子枝和根系的长度与粗度，在同一表面上连续插值。二维预览读取poseFrames和重复采样标记；旧数据格式继续使用既有分支，不受新资产元数据要求影响。这三姿态只是局部方法测试，尚未按参考完成完整幼苗到宽冠古树的美术设计。

## 实际二维结果与范围

用独立Flutter入口、同一网格/UV和图像着色器实际绘制了三个姿态、430手机视口、接头近景与101状态连续短片，未播放离线图像或阶段树图。最终证据来自build/qa/authored-surface-2d/2026-11-02T11-42-15.018Z；首个采集没有近景，追加近景流程后重新采集，最终证据不混用两次性能结果。

已查看实际二维近景、三个姿态、离线木体和控制线框：分叉与根颈有连续体积，树皮细节可读，上一整树自动分图造成的大量模糊黑片未在本片段中重现。沿枝纹理方向在接头仍可能有过渡差异，二维比离线更暗，法线光照是近似；这些都不等于最终材质统一通过。根梢仍尖、根系排列规则、主干顶梢呈尖杆，本资产没有叶冠和纸牌，不能冒充完整视觉。

## 验证与复现

1. Blender 4.5.9：--background --python tools/tree_scene/rectification/authored_surface_proof.py，输出build/qa/authored-surface-proof。
2. Flutter：build web --release --no-pub --source-maps --target tools/tree_scene/volume_mesh_preview.dart --output build/volume-web。
3. node tools/tree_scene/scripts/capture-volume-2d.mjs --surface；UV审计使用audit-volume-uv.mjs build/qa/authored-surface-proof。

静态分析无问题，独立release构建成功，实际源生成、JS语法与浏览器流程通过。同一Dart构建对旧简化片段再次运行，坐标校验和浏览器流程通过，result保存在legacy-regression.json；该结果仅证明旧元数据分支仍能运行，不改变旧视觉失败结论。未运行无关页面测试，也不称为全项目通过。

证据已复制到[控制面与沿枝UV验证/index.html](控制面与沿枝UV验证/index.html)，不依赖build目录留存。完整网格、源快照和日志另存电脑迁移包/本地备份/验收记录/2026-11-02-控制面与沿枝UV验证。正式lib、web、pubspec、旧母版与小说数据库均未改。

最终证据复核：八图全部加载，10.1秒视频在2.5/5/7.5秒均可解码，430宽审查页无横向溢出。当前Dart、源脚本、网格、元数据与材质哈希一致；材质确为声明的原图，旧分支结果对应同一Dart构建。evidence-check.json保存检查结果，代码地图已重新生成。这些检查只保证证据身份与可读性，不改变A2未通过的状态。
