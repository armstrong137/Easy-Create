# 魔树完整植株素材调查报告

## 结论

当前问题确认为素材路线问题，不是 App 播放代码问题。

现有 28 帧本质是“成熟魔树自下而上揭开”。它虽然连续、清晰，但早期帧不是完整小树苗，而是成熟树的下半截。用户最新目标要求每一帧都是完整植株：有根、有主干、有树冠，且从小树苗自然长成大树。

## 已加入的验收判据

`scripts/validate_magic_tree_frames.py` 新增两条回归防线：

- 非揭开：抽查 `f08/f10/f14/f18/f22/f26` 与 `f28` 在重叠前景区域的平均像素差，最低值必须 `>= 20`。
- 每帧有冠：每帧植株顶端 15% 高度内的绿色像素覆盖必须 `>= 30%`。

用新判据复验当前工程素材时，当前素材失败：`not_reveal_sequence: false`，最低重叠差约 `0.826`，说明早期帧仍与末帧下半截高度相同。

## 尝试过但放弃的路线

1. 重新拼接完整植株：能通过“非揭开”，但出现明显贴片方块、相邻帧差过大，画面不精致。
2. 在现有帧顶部补冠并给植株重新调色：连续性保留，但根部旧污染、绿色边缘和局部手绘感明显，不符合审美目标。
3. 从干净参考图重新做揭开并补冠：根部干净，但横向切口仍明显，本质没有摆脱“揭开”。
4. 用 ImageGen 生成 28 帧总表再拆帧：语义正确，但单格分辨率太低，拆帧后模糊、边缘粗糙，不能作为高清 App 素材。

## 下一步建议

要真正达到目标，需要重新生成素材源，而不是继续后期修补：

- 使用 img2img 链式生成 28 张单帧高清图。
- 每一帧以上一帧为输入，低重绘强度，只允许“主干更高更粗、叶片数量增加、树冠变密”。
- 固定相机、固定土堆、固定背景 `#FDF6EC`。
- 每帧单独输出 941x1672 JPEG，再跑现有 validator。

禁止再使用以下路线：

- 成熟树等比缩放。
- 成熟树自下而上揭开。
- 低分辨率总表拆帧后放大。
- 后期贴图层或色块补树冠。
