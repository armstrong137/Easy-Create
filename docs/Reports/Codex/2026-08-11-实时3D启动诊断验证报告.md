# 实时 3D 启动诊断验证报告

日期：2026-08-11

## 根因

1. 源码在异常边界之外构造 `MagicTreeScene`。浏览器无法创建 WebGL 上下文时，代码来不及发出可定位的错误事件。
2. Flutter 端只记录 `ready` 与静态回退两个布尔状态。WebGL、模型下载、纹理解码和首帧失败全部表现为同一个 8 秒超时。
3. `assets/tree_scene/dist/main.js` 曾有手工止血修复，但 `tools/tree_scene/src/main.js` 未同步，重新构建会覆盖修复。
4. 旧的 WebGL2 诊断只检查接口名称是否存在，禁用 WebGL 时仍会误报可用。

## 整改

- 启动阶段固定为 `iframeLoading / webglCreating / modelLoading / firstFrame / ready / failed / timedOut`。
- WebGL 构造与模型加载全部置于同一异常边界。
- `scene.error` 保留失败阶段、错误消息、实际 WebGL2 上下文能力、用户代理和模型 URL。
- Flutter 控制器保存最新阶段与完整错误载荷；显式错误不会被迟到的超时覆盖。
- `src` 经 `npm run build` 生成 `dist`，不再维护两套行为不同的入口。
- 新增 `tools/tree_scene/scripts/check-startup.mjs`，直接以真实 Chrome 验证成功与无 WebGL 两条路径。

## 自动验证

- `npm test`：23/23 通过。
- Flutter `tree_scene*_test.dart`：36/36 通过。
- `flutter analyze`：无问题。

## 浏览器证据

正常 SwiftShader 路径：

- 阶段顺序：`iframeLoading → webglCreating → modelLoading → firstFrame → ready`
- 首帧非背景像素覆盖率：`0.1088831221`
- 浏览器错误：0
- 截图：`build/magic_tree/browser/startup-ready.png`

禁用 WebGL 路径：

- 阶段顺序：`iframeLoading → webglCreating → failed`
- 错误阶段：`webglCreating`
- `webgl2Available=false`
- 截图：`build/magic_tree/browser/startup-error.png`

## 结论

浏览器空白现在可以被精确定位到启动阶段，且不再阻断 Flutter 业务编辑。此报告只验收启动与兼容路径，不代表当前古树美术质量达标；古树模型、材质、成长、枝条与标签仍按后续任务重建。
