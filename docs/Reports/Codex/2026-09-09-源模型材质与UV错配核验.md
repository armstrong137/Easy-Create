# 源模型材质与UV错配核验

## 本轮检查

Blender读取当前源文件，贴图均有打包数据，不是简单的贴图路径缺失。TrunkSkinned混用两个树皮材质，Roots独立使用其中一个材质；预览重建叶片的UV矩形对应项目leaf_atlas_rgba.png，实际选取材质却来自导入的island_tree_01叶片。

## 对照试验

仅在内存场景中重建匹配项目叶片图集的材质，将根部暂时指向主干材质，并按可见几何包围盒重新取景。没有保存或覆盖.blend文件。

输出 `picture/魔树动画素材/本地渲染核验/mature-material-probe.png`，本地EEVEE渲染约11秒，退出0，1536×2730 RGBA。

## 结论

- 取景不再横向裁断主体，但当前树形偏宽矮，与批准的参天古树差距明显。
- 根部替换材质后出现明显拉伸/碎片状纹理，证明不能只统一材质引用，必须匹配UV。
- 根部多边形轮廓、树干脚部以及大量叶簇分布仍不自然。
- 本次相机、材质、贴图同时改变，不能将画面整体变化归因于单一项；叶片错配由代码和绑定关系直接确认，视觉效果仍需进一步单变量核验。

**不接入生产，也不保存这个试改模型。** 这不是“调亮/调色即可达标”的问题；下一步应针对根部几何与UV做结构性修改，再处理树冠，而不是继续提高同一坏模型的输出像素数。
