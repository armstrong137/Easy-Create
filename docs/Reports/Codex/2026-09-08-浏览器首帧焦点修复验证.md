# 浏览器首帧焦点修复验证

## 范围与结论

修复阻断大纲浏览器验收的启动错误，不代表古树视觉目标完成。发布版以同一检查脚本复测，退出码 0、浏览器错误为空；26 项局部测试通过。枝根拼接、真实连续生长、历史视野移动和成熟态书名对比度仍需整改。

## 根因证据

调试构建中，即使不点击、不启用语义，页面启动也会报告：

```text
WidgetsBindingObserver.didChangeViewFocus
RenderBox was not laid out: RenderSemanticsAnnotations NEEDS-LAYOUT
```

分别测试无操作、Tab、点击语义占位节点，错误均在操作前出现。监听 `flutter-first-frame` 确认错误发生在首帧之前，不能靠让验收脚本晚几秒点击规避。

Chrome 调试协议捕获到异常栈：

```text
RenderSemanticsAnnotations.get$size
RenderSemanticsAnnotations.get$semanticBounds
FocusScopeNode.get$rect
ReadingOrderTraversalPolicy_sort
FocusTraversalPolicy__sortAllDescendants
ReadingOrderTraversalPolicy._findInitialFocus
didChangeViewFocus
handleViewFocusChanged
```

本机 Flutter `widgets/view.dart` 在收到 forward 焦点事件后立即调用 `findFirstFocus`；当根控件尚未完成布局，读取焦点节点矩形会抛错。这不是树图加载失败，也不是创建章节事务失败。

## 修复

- 新增 `StartupFocusGuard`，仅暂存首帧布局前的最新焦点事件，在 `drawFrame` 完成后转发。
- 首帧以后立即走原有焦点处理，不加固定毫秒延时、不忽略异常、不改焦点遍历策略。
- `main.dart` 只在 Web 入口采用该绑定，iOS/Android 原有初始化不变。
- 测试通过真实绑定的 `drawFrame` 验证：布局前未通知观察者、先失焦后获焦只保留最后的 forward 获焦事件、首帧后事件即时通知。
- 独立审查指出仅检查事件列表不足，本轮补充观察回调当时 RenderBox 的 `hasSize` 检查。刻意将转发移到 `super.drawFrame()` 前，测试观察到 `false` 并失败；恢复后通过。该测试仍不替代真实页面焦点遍历，后者由浏览器端到端检查覆盖。
