# 共享图集两级分叉：局部验证

## 实际结果

主干、一级枝和二级枝使用同一不透明图集及固定 UV。已查看局部三姿态和近景：两个接头木纹连续，未出现之前全局 UV 平均导致的黑带；新灰橄榄棕材质比原偏红源稿更接近参考，但二级枝梢仍偏针状，接头纹理也有局部拉伸。

本次没有根冠、木牌或完整幼苗，不能将局部四图当作 A2 整树四图。十六套完整方案两轮淘汰状态不变，A2 未通过，正式应用未接入。

## 接入口的实际几何

先行大接面把一级枝连续九行都用作二级基圈，实际图像呈鳍片，未采用。最终只使用一级枝第 13 至 15 截面的两条上缘边，分别四分细分，共增加六个母体顶点和六个母体三角。

二级枝的九点基圈直接复用 `[701,801,802,803,710,804,805,806,719]`；二级枝没有独立封口贴上母枝。母体边细分与二级枝共用同一索引，原母枝轮廓不因细分改变。各阶段二级长度独立指定，不缩放整棵成熟树。

最终 1023 顶点、1798 三角，分为主干、一级枝、二级枝三个材质归属域；两级父子接合实际共 16 条边。全幅材质源 `hierarchical_fork_bark_field_v1.png` 通过 imagegen 技能和内置工具生成，源稿及完整提示词已入项目，未使用 CLI 后备路径。它只提供材质方向，真实轮廓由上述几何决定。

## 验证及结论范围

- 独立读取归档 PNG、UV、面索引和网格二进制：800×1440 图集全像素不透明、固定 UV 在界内且非退化，图集面与原生面一致。
- 从实际边邻接核对父子域对应及 16 条共边；开放木质表面完整连通，没有非流形边或共享面的反向错误。
- 修改二级枝父域为主干、同时改动二级枝真实面索引与图集面以断开接边、将图集像素改透明，三个反例均被拒绝。见 `negative-controls.json`。
- `audit-cage-intervals.mjs` 对实际 Float32 二进制的 0–0.18、0.18–0.5、0.5–1 三个完整顶点插值区间求面积二次式极小值，1798 三角均通过原舍入误差界，最小余量约 `3.294×10⁻⁸`。仅适用于 X-Z 正交投影及这些线性插值姿态，不是自然造型、GPU 像素或手机性能验收。
- 41 帧实渲无相对成熟面的翻转，视频 8 fps；Chrome 实际解码时长 5.125 秒，并查看 2.5 秒中段。编码帧率不是实际运行帧率。
- 单分叉入口重新实渲，四张 PNG 的 SHA256 均与 `7505627` 归档相同；该旧输入几何和素材未覆盖。

`atlas-audit.json`、`interval-audit.json`、`result.json` 及 `video-review.json` 保存当前检查结果。归档包含实际输入/输出网格、图集和坐标，可独立核对，不能将这些局部技术检查代替整体参考复审。
