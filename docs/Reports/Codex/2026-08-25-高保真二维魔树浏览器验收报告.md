## 一、决策与目标

用户最终明确：不一定采用 3D，好看的 2D 可以接受，核心要求是实际浏览器 UI 必须与
批准渲染图保持同一美术方向。由此，正式验收从“是否实时 3D”改为以下结果门槛：

1. 魔树必须是完整树苗到宽冠古树的连续叙事，不得是仙人掌、直筒或成年树裁切。
2. 章节只在左侧、小节只在右侧，二者都必须由真实树枝承托，不能用系统卡片或连线。
3. 新建章/节时树体先变化，新枝随后从树干侧一次长出；浏览历史内容只移动窗口。
4. 树、背景、标题和枝牌必须属于同一画面，不得有顶部色带、抠图灰边、矩形底板、
   半透明残影、硬切口或悬空枝。

## 二、正式实现

- `TreeStandin` 使用六张 941×1672 高清完整古树插画，按结构树龄映射 `age_0` 至
  `age_5`，以 920ms 柔和淡入和底部锚定微缩放完成阶段过渡。
- `IllustratedBranchPlaque` 使用 1536×1024 透明枝牌精灵。枝干、叶片、木牌与羊皮纸
  牌芯是一个美术实体，靠树干端在画布 82% 左右形成不规则根颈，边缘以真实 alpha
  抗锯齿，不依赖黑色底图或大范围羽化。
- 新枝先等待 240ms，再用 920ms `easeOutCubic` 裁剪显露；文字、选中金边与枝干一同
  受裁剪，不再把标签当作独立贴图上下移动。
- 正式路径默认关闭 WebGL 魔树，只有编译时传入
  `ENABLE_EXPERIMENTAL_TREE_3D=true` 或测试注入场景构建器时才启用实验 3D。

## 三、430×932 浏览器结果验收

使用本地 release Web 构建，在 430×932 手机视口完成以下操作：

| 场景 | 结果 |
|---|---|
| 一章一节首次进入 | 树景覆盖状态栏下整个页面，标题直接叠在背景上，无顶部色带 |
| 新增第二章 | 树先切到下一结构阶段，新章枝随后完整长出，数据库写入成功 |
| 当前章新增两节 | 两条小节枝只出现在右侧，牌芯文字清晰 |
| 左侧下滑到早期章 | 章节焦点变化，成熟树保持成熟，不退回幼苗 |
| 退出后重新进入 | 默认回到最新章节，其最新小节窗口可见 |
| 四枝稳定态 | 两章两节全部与主干重叠，无树根以下悬空枝 |

最终逐像素肉眼检查结果：

- 顶部背景连续，无独立纯色导航带。
- 树图与背景无照片矩形边界。
- 枝牌透明区无黑金雾、灰边、棋盘格、方形裁切或低分辨率 alpha 阶梯。
- 根颈为不透明自然树皮轮廓，未使用会产生鬼影的宽羽化。
- 当前章与当前节以牌芯金色内发光区分，未增加额外卡片。
- 速记按钮、灵感卷轴、返回按钮不遮挡可见牌芯。
