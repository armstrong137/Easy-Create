# 参考主导构图与统一源资产预制作

当前完成批准参考的可编辑结构引导，以及同源木体、九组冠簇和左右枝牌源稿。它们是下一套样件的制作输入，尚未导出新运行时网格，也没有新四图或成长短片。A2仍未通过，六套完整方案两轮拒绝的历史保留。

## 本轮假设与范围

成熟树的枝架、冠层和承托枝必须共同设计，不能继续用旧五肩枝配通用叶扇填空。保留已经验证的二维绘制、固定UV、实体端口及安全形变工具；本轮只改变独立源资产和制作工具，不改正式页面或数据库。

人工结构引导记录七个错落主枝方向、九个相互搭接的冠层体块及两个阅读区。JSON可编辑，SVG和PNG由render-reference-composition.mjs重建；不是逐像素描摹或最终挂点坐标。引导尺寸1089×1444，新木图1089×1445，不能默认两者像素坐标完全相同。

## 实际源稿与核对

使用imagegen技能及内置image_gen，以项目批准参考和结构引导制作源稿。原PNG透明通道保留，无本地像素清理；每张实际提示词、输出来源、尺寸和SHA256均已保存。查看[源稿并排页](参考主导统一源资产/index.html)与[sources.json](参考主导统一源资产/sources.json)。

| 源稿 | 实际结构 | 仍需解决 |
|---|---|---|
| reference_wood_v1 | 一块主体、错落主次枝和自然细梢，非旧五指结构 | 根尖仍偏锐，幼态老木纹未解决；有100个不超过100像素的边缘小连通区 |
| reference_canopy_v1 | 九块不同形状的局部叶枝，统一橄榄叶色与木质 | 不是严格九宫格：C1到x506，越过第一等分线418；必须按实际连通区取UV，前后遮挡和成熟冠层整体尚未实渲 |
| reference_frames_v1 | 两块直接承托的细边长窗木框，左右保留原光向 | 编辑后检查窗内共7像素alpha=1；不能登记为完全透明通过，真实母子实体挂点尚未验证 |

框首稿两个空窗样点alpha为186/149，并有外沿灰晕，未选入项目源稿。一次内置透明提取后，同样样点均为0，木质仍实体；但完整检查两个内接矩形分别发现4和3个alpha=1像素。因此源审计如实记录exactTransparentApertures=false，不用缩小矩形或放宽定义伪造通过。提取也改变了少量木纹颜色，不能宣称原木体像素完全不变。

alpha≥128的主连通区数量分别1、9、2。此检查只证明源图存在这些区域，不证明自然成长、无翻面、实体接合、材质统一或性能。未把这些数字记为A2通过。

## 验证与复现

1. 修改引导JSON后运行node tools/tree_scene/scripts/render-reference-composition.mjs，检查标签和阅读区。
2. 分别运行inspect-illustrated-atlas.mjs --reference-wood、--reference-canopy、--reference-frames，生成只读连通标签；不加新参数时保留旧路径。
3. 运行audit-reference-sources.mjs，核对PNG哈希、主构件数和实际空窗矩形，输出源审计JSON。
4. 审查并排页的全部图片和提示词链接，检查430宽布局；源稿和引导均人工查看。正式Flutter未改，不冒充重测整树或业务流程。

本轮实际执行：三种新源分析、哈希/空窗审计、引导重建、两个新脚本语法检查及原默认图集/旧四冠簇参数回归均成功。浏览器载入5张图片、核对12个本地链接有效、页面错误0，430×932无横向溢出；结果保存review-check.json。源稿审计准确记录空窗不完全透明，命令执行成功不等于源稿全部达标。提交前已同步索引并重建代码地图。
