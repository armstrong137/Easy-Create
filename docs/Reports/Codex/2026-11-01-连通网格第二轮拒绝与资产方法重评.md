# 连通网格第二轮：视觉拒绝，停止自动造型路线

新连通网格路线已经交付第二套完整四图及连续成长短片，整体仍未达到参考，**A2不通过**。按两轮上限，停止“节点球/锥形枝体积并集＋自动简化/分图＋参数化叶位”作为最终美术资产的制作路线，不继续第三轮造型调参，也不进入正式集成。保留导出和独立二维绘制工具作技术证据，不能将保留工具解释为该资产方案通过。

## 第二轮实际变更

- 七组主枝改为更低处分叉、向上拱起；粗根从更高根颈落地，不从同一低点平摊。
- 幼龄主干长度与宽度分别变化，早生叶从上部主干挂点抬升；没有成年整树缩放或阶段换图。
- 使用新生成的四种局部哑光单叶图集，沿当前枝段交错排布；实际透明像素已检查。它只提供局部材质，不替代整树生成。
- 木框沿闭环逐段连接，纸面四角取当前框角内缩并共同变形，文字按同一投影变换；纸面随成长渐入。绘图区裁剪后不再覆盖顶部树龄行。
- 同一木质表面刻入沿枝木脊，增大树皮纹理尺度，连续多投影烘焙仍为固定2048图集。

首次生成因细梢低于体素解析能力而出现多个不连接体，被检查拒绝。提高解析精度并调整最细截面后重新生成，未删除断块来伪造连通。最终16484顶点、32984三角形，一个连接体、零非流形边；二进制2572080字节，基色图集1309985字节。原失败日志已独立保留。

## 完整视觉结论

| 项目 | 改善 | 仍不合格之处 |
|---|---|---|
| 宽冠 | 主枝不再逐层横平伸出 | 仍是规则扇枝/叉架，缺少参考的有机扭结、冠团和前后层次 |
| 幼苗 | 从低叶裸尖改为上部展叶 | 细干扭曲、叶柄横排像梯架，不是可信完整树苗 |
| 根颈 | 高根向地面落下，裙边减轻 | 粗根仍板结，根干过渡、落地与阴影未自然统一 |
| 材质 | 新叶片明显减少强反光；加入木脊 | 树皮严重模糊，并有黑片/三角痕，叶片仍像规则稀疏阵列 |
| 枝牌 | 纸面位于框内，标题可读、共同变形 | 牌框仍像规则硬框，未形成参考的自然木质承托风格 |
| 构图与成长 | 顶部信息不再被近景覆盖；网格连续形变 | 宽屏边缘冠梢接近/触及画幅，生态比例与展叶节奏仍未通过 |

已查看幼苗、中龄、成熟和近景；本轮没有因局部改善而放行。短片是固定900×1280相机下101个真实Flutter网格状态，树龄0至1，显示树龄与时间，约10.1秒。编码10fps不是运行帧率。手机图来自430×932浏览器视口，不是真机。

## 重新评估的直接证据

相同源资产在Blender离线木体图中也有黑片和纹理模糊，问题不能只归因于Flutter。审查页同时保存offline-wood.png和实际图集。没有通过提高环境亮度或更改浏览器参数掩盖源问题。

新增只读audit-volume-uv.mjs，检查实际导出三角形在2048图集中占用的像素面积：

| 实际UV指标 | 首轮 | 第二轮 |
|---|---:|---:|
| 三角形数量 | 19310 | 32984 |
| UV面积中位数 | 5.654像素² | 0.168像素² |
| 面积小于1像素² | 335 | 31985（约97%） |
| 三角UV面积总和/图集面积 | 3.874% | 0.222% |

图表数量和边距造成的纹理预算浪费已实际暴露：增加网格和表面细节没有增加可读材质。上述面积总和不是去重覆盖率，不证明图表不重叠，也不足以认定黑片的唯一原因；自交、图表边缘和采样仍可能参与。数据及网格/元数据/图集哈希保存在uv-round1.json、uv-round2.json。不能将“小片段能烘焙”推断成“整树资产方案已解决”。

## 下一项决策：先重新制作美术源资产

| 方法 | 决策 |
|---|---|
| 第三轮继续调球体/锥体、叶位、光照和烘焙边距 | 停止；不能把技术修补重命名为新美术路线 |
| 放回旧整树阶段图或缩放成年树 | 禁止，违反连续成长与挂点要求 |
| 直接用旧Blender母版替换 | 不采用；旧视觉失败及格式兼容问题仍存在 |
| 按参考制作有明确根颈/分叉控制面的源网格、按解剖部位规划UV和成长关键姿态，再导出二维投影 | 下一项评估；不继承自动并集模型为最终形体，不宣称已经选型成功 |

下一项要改变资产制作方式：先建立可编辑的根颈和母子分叉控制面，让轮廓、扭结与UV沿实际解剖部位设计；材质必须有足够像素密度，不能对大量小三角自动分图。幼龄与成熟姿态在同一控制拓扑上按参考制作，叶冠先确定真实支撑和团块，再铺局部叶片。二维drawVertices仅作为可复用的运行工具，是否满足最终遮挡与手机预算仍待验收。

这是两轮失败后的方法重评，不是第三轮参数优化。新的资产方法即便局部通过，也必须重新交付完整四图与连续短片、对照参考整体审查后，才能进行A3至A6。目标完整保留，不改成“烘焙工具完成”或“文档完成”。
