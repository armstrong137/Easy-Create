# 魔树美术自动验收规范

> 日期：2026-08-11  
> 范围：五阶段离线渲染图与成熟移动端浏览器截图  
> 工具：`scripts/validate_magic_tree_visuals.py`  
> 原则：自动门槛只拒绝明显错误；`manualReviewRequired` 永远为 `true`，不能替代用户终验。

## 一、输入与执行

脚本固定接收按树龄从小到大排列的五张离线渲染图、一张成熟浏览器截图，以及三张批准参考图。五阶段图片必须使用相同画布尺寸。

```powershell
python scripts/validate_magic_tree_visuals.py `
  --stages <阶段1> <阶段2> <阶段3> <阶段4> <阶段5> `
  --mature-browser <成熟浏览器截图> `
  --front-reference assets/source/magic_tree/references/树形正视图.png `
  --growth-reference assets/source/magic_tree/references/五阶段成长分镜.png `
  --support-reference assets/source/magic_tree/references/章节目枝直接承托效果图.png
```

标准输出始终为 UTF-8 JSON。退出码：`0` 为自动门槛通过，`1` 为视觉指标拒绝，`2` 为文件缺失、解码失败、五阶段画布不一致或未检测到主体。

## 二、轮廓提取

1. 带透明通道的离线图以 `alpha > 24` 为主体，不把透明底误判为黑色背景。
2. 不透明图从四边各 2% 像素估计背景；像素亮度比背景低 32、RGB 距离大于 38 时进入主体掩膜。
3. 成熟轮廓比较统一底部基线和高度，但不拉伸宽度；宽高比例差会保留在 silhouette IoU 中。
4. 树冠采样主体高度的 12%~58%，主干采样 62%~78%，根系采样 84%~99%。每个带使用逐行轮廓宽度的 P80 或 P50，避免单根异常长枝决定结果。

## 三、参考图校准

阈值在每次执行时由批准参考图重新计算。当前批准图得到以下基线：

| 基线 | 当前测量值 | 门槛公式 | 当前门槛 |
|---|---:|---|---:|
| 成熟轮廓宽高比 | 0.797725 | 参考值 × 0.90~1.08，并限制在 0.62~0.90 | 0.717952~0.861543 |
| 归一化 silhouette IoU | - | 已批准 G1 硬门槛 | ≥0.88 |
| 树冠逐行宽度 P80 | 0.931772 | 参考值 × 0.88 | ≥0.819959 |
| 树冠区域填充率 | 0.624850 | 参考值 × 0.90 | ≥0.562365 |
| 根系逐行宽度 P80 | 0.744807 | 参考值 × 0.95 | ≥0.707567 |
| 根幅/主干宽度 | 2.802302 | 参考值 × 0.75 | ≥2.101726 |

`五阶段成长分镜.png` 在五个树干中心采得相对成熟树高 `0.276203 / 0.491985 / 0.676942 / 0.819975 / 1.000000`。据其最小相邻增量取 15%，得到每阶段最低树高增量 `0.021455`；冠幅、根幅和前景面积允许 `0.01` 的抗锯齿容差，但不得发生更大回缩。

三张批准图顶部明亮低色度区域的中位背景为 RGB `254/247/223`。背景门槛为：中位色距离不超过 `18`，偏色像素占比不超过 `0.12`，顶部及侧边污染不超过 `0.04`。内部矩形接缝以批准承托图水平/垂直长直纹理的较小值乘 `1.5` 校准，当前两向同时达到 `0.478215` 即拒绝，避免把单独的纵向主干纹理误报为矩形底。

移动端成熟主体高度直接采用整改计划硬要求：占截图高度 `78%~90%`。

## 四、JSON 判定

`checks` 固定包含六项：

- `silhouette_dimensions`：成熟轮廓宽高比与 silhouette IoU。
- `crown_spread`：树冠横向展开与树冠填充率，拒绝柱状、针簇和仙人掌式树冠。
- `root_spread`：根系横向宽度与根颈相对主干外扩。
- `growth_monotonicity`：五阶段树高、主体宽度和前景面积序列。
- `background_boundary`：浏览器截图和五张阶段图各自的背景色、偏色面积、外沿污染、内部矩形长直接缝和透明像素；阶段明细写入 `stageMetrics`。
- `mobile_composition`：成熟树在移动端截图中的主体高度占比。

每项均输出 `pass / metrics / thresholds / failures`。顶层 `pass` 只有在六项全部通过时才为 `true`；`failures` 汇总稳定的失败代码，便于 CI 或发布脚本读取。

## 五、当前失败基线

为避免生产 stand-in 被并行美术任务改写后让回归基线漂移，测试从固定的 `mature-430x932.jpg` 在临时目录生成五张相同画布的递增阶段图，最后一张保持原失败截图。该固定夹具实测退出码为 `1`：

| 检查 | 当前值 | 结果 |
|---|---|---|
| silhouette IoU | 0.585567，要求 ≥0.88 | 拒绝 |
| 树冠宽度 P80 | 0.913022，要求 ≥0.819959 | 通过 |
| 树冠填充率 | 0.647367，要求 ≥0.562365 | 通过 |
| 根系宽度 P80 | 0.681081，要求 ≥0.707567 | 拒绝 |
| 五阶段主体高度 | 0.157725 / 0.245708 / 0.328326 / 0.422747 / 0.521459 | 通过 |
| 五阶段主体宽度 | 0.286047 / 0.444186 / 0.597674 / 0.767442 / 0.946512 | 通过 |
| 五阶段前景面积 | 0.022872 / 0.055118 / 0.098421 / 0.161995 / 0.246005 | 通过 |

因此当前柱状/仙人掌树即使背景干净且人为缩放序列单调，也会被轮廓、根系和移动端构图三个独立门槛阻断。实际离线阶段图若含透明底、灰边、矩形接缝或成长回缩，会继续追加对应失败代码。

## 六、测试与人工门槛

执行测试：

```powershell
python -m unittest discover -s test -p 'test_validate_magic_tree_visuals.py' -v
```

测试覆盖当前失败素材必须拒绝、参考树形五阶段正例可通过、内部矩形接缝必须拒绝、阶段透明边必须拒绝。自动报告不判断树皮品质、叶簇美术、木牌是否真正由枝梢承托、动画连续性或交互可靠性；这些项目仍须按现有 G3~G7 标准提交截图、叠图、录屏并由用户明确终验。
