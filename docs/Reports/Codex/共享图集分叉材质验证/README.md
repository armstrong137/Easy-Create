# 共享图集分叉材质：局部验证

## 当前结果

原生母子分叉使用同一全幅树皮图集和固定 UV。实际接头图中，木纹能从主干转入侧枝，没有独立木条贴片横缝或原全局 UV 平均产生的黑带。局部早态、中态、成熟态、接头近景和 41 帧形变短片已归档。

当前材质偏红、偏暖，接头仍有拉伸，表面厚度与批准参考有差距；没有根、冠层、木牌和完整幼苗。不能将这四张局部图算作 A2 整树四图。十六套完整候选两轮淘汰状态不变，A2 未通过。

## 两种材质路径的实际对照

`流线反查近景.png` 是先行方法：从已有不透明树皮源沿方向场反查基部纤维标签和长度。虽然流线均抵达基部、坐标有限，但侧枝出现横向条带，说明材质方向和尺度仍不可用，未扩展为整树。

随后通过 imagegen 技能、内置 `image_gen` 生成全幅共享树皮域 `shared_fork_bark_field_v1.png`。它是可贴到几何上的材质场，不是阶段整树图；图集外观由统一图像决定，真实木体轮廓由三角网格决定。源码材质、完整提示词及出处在 `assets/source/magic_tree/textures_source/shared_fork_bark_field_v1.*`。没有使用 CLI 后备路径，也没有替换已退役整树的默认入口。

`atlas.png` 是运行时实际使用的 800×1440 图集：共享原生几何的成熟表面投影决定固定 UV，并按原生法线附加轻量体积明暗。生长只改变顶点位置与同一纹理位置的细节强度，不重新平均各枝 UV，不重排木纹。幼态仍沿用成熟法线明暗，独立幼态材质和自然造型尚未完成。

## 独立检查及边界

`audit-shared-bark-chart.mjs` 从归档的实际 PNG、图集坐标、面索引和原生二进制独立读取：

- 图集 1,152,000 个像素全部不透明，801 个 UV 均有限且在界内。
- 1408 个图集面与输入原生面完全一致，母子保留 8 条实际共享边。
- UV 三角均非退化，最小有向二倍面积绝对值约 17.031 平方图集像素。
- 将实体采样处的一个 alpha 改为零、将实际 UV 改到界外，两个反例均被检查拒绝，见 `negative-controls.json`。

全幅不透明图集和界内固定 UV 的组合，避免了之前随龄反查到源透明空域的失败类别；这不是对错误采样补默认木色。几何三角覆盖负责透明轮廓，材质域本身不挖空。

41 个实际绘制姿态均未发生相对成熟面的翻转，最小二倍投影面积约 0.003485 平方视口像素。这里只证明离散采样，不重新声明所有连续时刻的几何安全或手机性能。局部网格输入 SHA256 记录在 `result.json`；四姿态原生网格为已有 801 顶点版本，未修改其生成器。

`deformation.webm` 为 41 帧、8 fps。已在 Chrome 实际解码，时长 5.125 秒，查看 2.5 秒中段，见 `视频中段.png` 与 `video-review.json`。编码帧率不是运行帧率结论。

## 复现

若原生输入不存在，先用项目 Python 运行 `tools/tree_scene/rectification/branch_development_proof.py`，不加 `--root-collar`，生成 `build/qa/branch-development-proof`。随后在项目根目录运行：

```powershell
& 'D:\Node.js\node.exe' tools/tree_scene/scripts/probe-transported-bark.mjs --painted
& 'D:\Node.js\node.exe' tools/tree_scene/scripts/audit-shared-bark-chart.mjs
```

本目录保存了实际 `mesh.bin`、`mesh.json`、`chart.json` 和 `atlas.png`，可直接将本目录作为审计器参数重新核对，无须依赖会被覆盖的 build 输出。

下一项验证第二级真实父子分叉和根颈的材质连接，再制作统一根冠、承托枝牌及完整幼苗样件。这个单 Y 分叉只解决局部贴图问题，不能直接恢复任何已淘汰造型，不进入正式应用。
