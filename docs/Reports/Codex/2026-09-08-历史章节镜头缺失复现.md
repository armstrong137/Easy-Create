# 历史章节镜头缺失复现

## 实测

命令（在 tools/tree_scene 下）：

```sh
node scripts/check-illustrated-outline.mjs http://127.0.0.1:8780/ ../../build/illustrated-history-check --audit-history
```

创建十章两节后，九次左侧拖动回到引子。语义节点确认引子已出现；截图显示引子、第一章替代第八、第九章，但树体完全未移动。

输出：`build/illustrated-history-check/2026-09-09T02-06-26.959Z/`。

`history-audit.json` 中 reachedPrologue=true、treeRegionChanged=false；检查位置为屏幕 x200,y650,width30,height160，避开枝牌。命令退出1，断言“滑回引子后树干区域完全未变”。已肉眼检查 history-prologue-430.png，与成熟态背景一致。

注意：区域不同仅为必要条件，不是镜头正确的充分条件；闪光、重新换树也会改变像素。后续必须目视核对树龄保持、镜头方向和枝牌连接。

## 数据流根因

1. outline_page.dart 的左侧拖动调用三维控制器 pan，正式二维 TreeStandin 未接收此数据。
2. TreeStandin 只有 stage、growthRevision，图像固定 bottomCenter。
3. windowLabels 由当前窗口序号0/1计算屏幕 top，同一章没有持久的场景高度。
4. 因此仅对 TreeStandin 加 Transform 将造成树与枝牌脱离，不是有效修复。

## 修复必须同时覆盖

- 树龄继续由总结构节点决定，禁止由选中章节决定。
- 树体、章枝、节枝使用同一个场景坐标到屏幕坐标转换；点击和拖拽区域使用相同变换。
- 章节点保持稳定的场景位置，左侧最多显示两个交互标签；焦点变化移动镜头而非给同一屏幕槽位换文字。
- 右侧切节不改变左侧章节焦点，镜头变化不能误触新增或编辑。
- 成熟树必须有可浏览的根至冠画幅；当前最终图冠部已超出边界，单纯放大现有截幅无法提供缺失的树冠。
- 验证九次滑回引子、再滑回最新章，比较树龄和节点稳定性，并录制完整过程。新检查失败状态不得标成已修复。

本次交付是可执行的失败验收和根因证据，没有修改生产交互，整体目标仍未完成。
