# 实时 3D 魔树失败复盘与彻底整改计划

> 日期：2026-08-11  
> 范围：原因调查与整改计划，不修改生产代码  
> 结论：当前实现不得继续作为“实时 3D 魔树完成版”验收或发布

## 一、结论

用户的判断完全正确：当前大纲页与已批准效果图不是“细节有差距”，而是产品形态、树种、美术质量、场景构图、交互入口和运行路径均不一致。

本次失败不是单个参数或单张贴图导致，而是四层问题叠加：

1. 正式手机页面没有稳定运行实时 3D，实际显示的是六张静态替身图。
2. 正式 3D 模型本身由数学曲线批量生成，树形与批准的古树参考图相反。
3. 新建章节只依赖不可见的左半屏双击，并与竖向滑动争抢手势，失败后没有任何反馈。
4. 已经写明的视觉终验门槛没有真正执行；明显失败的截图仍被自动化指标判为通过。

因此，不能在现有树上继续做局部修补。必须保留业务数据层，重建美术资产、3D 表现层、降级表现层和验收流水线。

## 二、已确认的直接证据

### 2.1 手机截图显示的是静态替身，不是实时 3D

用户截图中的幼苗和成熟树分别与以下文件一致：

- `assets/tree_scene/standins/age_0.webp`
- `assets/tree_scene/standins/age_5.webp`

代码链路：

- `tree_scene_web.dart` 启动后只等待 8 秒。
- 超时、`scene.error` 或连续恢复失败后，`TreeSceneController` 立即切换 `useStaticFallback`。
- 一旦进入静态模式，实时树 iframe 被移除，页面改用 `TreeStandin`。
- 原始 `scene.error.message` 没有持久化、没有日志面板，也没有出现在验收报告中，因此无法从用户截图还原手机端的真实启动错误。

这解释了为什么用户看到的是静态树、普通矩形标签和完全没有 3D 章节枝动画。

### 2.2 静态替身从素材本身就不合格

`TreeStandin` 使用 `BoxFit.contain` 将整张替身图放入大纲页：

- `age_0.webp` 的树苗只占画面底部极小面积，因此产生整屏留白、底部只露一点树尖的结果。
- `age_5.webp` 是细长针叶状树冠、截断枝梢、压扁圆盘土壤，与批准效果图的宽冠古树完全不同。
- 静态模式下章/节标签不是树枝托举的 3D 木牌，而是 Flutter `Container`：米白底、细边框、圆角和阴影。
- 标签位置是固定屏幕坐标，和真实枝梢没有几何连接。

所以即使静态回退工作“正常”，它也必然产生用户截图中的难看页面。

### 2.3 正式 3D 模型的生成路线错误

`scripts/build_magic_tree_blender.py` 不是对批准效果图进行艺术建模，而是程序化拼出一棵树：

- 主干由固定正弦曲线生成。
- 固定生成 9 根主枝，批准标准要求 5 至 7 根可辨识主枝。
- 每根主枝再固定生成 6 根次枝，形成规律、拥挤、缺少自然负空间的轮廓。
- 叶片使用同一张平面贴图沿枝条环形复制，造成针叶、仙人掌和剪纸簇感。
- 土壤是一个压扁的 UV 球，所以最终必然像悬浮圆盘。
- 幼苗阶段通过缩放成熟树骨架、枝条和叶片得到，不是独立塑造的完整幼树。

这条路线最多能生成技术占位模型，不能生成参考图里的宽冠、粗根、老树皮、苔藓、金色魔法纹理和自然分枝。继续调整曲线、数量或缩放参数没有意义。

### 2.4 新建章节入口在真实浏览器中不可用或极不可靠

当前交互：

- 左半屏 `onDoubleTap` 新建章节。
- 右半屏 `onDoubleTap` 新建小节。
- 同一块区域同时注册竖向拖动，用于切换章或节。
- 页面没有可见的新建入口、按下态、处理中状态、成功状态或错误状态。

本次在当前浏览器复现：对左半屏执行双击后，页面没有新增标签、树龄变化或任何反馈。现有 widget 测试只在测试环境里模拟两次 `tapAt` 并检查数据库行数，没有覆盖：

- Safari/真实浏览器触控事件。
- 双击与竖向拖动的手势竞争。
- 数据流是否重建页面。
- 新章节是否真正显示为枝条和标签。
- 写入失败时用户是否得到错误提示。

数据库事务本身结构正常，当前首要故障点是入口和端到端反馈链，而不是章节表设计。

### 2.5 验收流程失效

现有验收标准其实已经明确写出：

- 参考图、结果图、50% 透明叠图必须同时提交。
- 正视 silhouette IoU 必须达到 0.88。
- 正式手机视口必须验收。
- 只有用户明确通过，才允许默认开启 3D 并删除旧回退。

实际执行却只检查了文件存在、图片可解码、透明边、三角面数、主体非空和简单包围盒比例。代码中没有真正实现参考图 silhouette IoU、叠图差异或用户终验阻断。

更严重的是，`mature-430x932.jpg` 已经清楚显示了针叶状小树、圆盘土壤和普通标签，但仍被写入“完整验收报告”。这是验收判断失败，不是测试覆盖率不足可以解释的。

## 三、整改目标

整改完成后的大纲页必须同时满足：

1. **视觉一致**：树形、树皮、根系、冠幅、叶簇、金色魔法纹理、章节枝和木牌达到批准参考图的同一视觉语言。
2. **真实生长**：从完整小树苗成长为完整古树，主干变高变粗、根系扩张、树冠逐步增密；不得缩放成熟树或向上揭开成熟树。
3. **枝条即信息架构**：章节在左侧真实枝条上，最多显示两章；当前章的小节在右侧真实枝条上。木牌由枝梢直接托举，不得用连接线或屏幕悬浮卡片。
4. **交互可靠**：创建章节和小节必须有可发现、可点击、可反馈的入口；双击只能作为快捷方式，不能作为唯一入口。
5. **运行可靠**：目标 iPhone Safari、Android Chrome 和 Flutter 原生壳中优先进入实时 3D；无法进入时，降级画面仍与正式场景同源且业务功能完整。
6. **结果验收**：不以代码完成、测试通过或 `pass:true` 代替真实手机结果图和用户终验。

## 四、完整整改顺序

### Task 0：冻结错误版本并建立可复现基线

改动范围：配置、测试数据与验收目录，不改业务数据。

执行：

1. 当前程序化树、六张静态替身和现有验收报告标记为 `rejected`，不得继续作为正式素材。
2. 建立固定验收数据：0 章、1 章、2 章、5 章、10 章，每章 0/1/5/8 节。
3. 固定三档手机视口：`360×800`、`390×844`、`430×932 @ DPR 3`。
4. 保存当前失败截图、批准参考图和后续结果图，所有比较使用相同裁切与相机。

退出条件：任何人一条命令即可打开相同测试小说并复现当前失败画面。

### Task 1：先恢复章节和小节创建功能

主要文件：

- `lib/presentation/outline/outline_page.dart`
- `lib/presentation/outline/outline_controller.dart`
- `lib/data/repositories/novel_repository.dart`
- `test/presentation/outline_page_test.dart`
- 新增浏览器/真机集成测试

执行：

1. 在树的左右两侧分别增加小型“新芽 +”图标入口；左侧创建章，右侧创建当前章的小节。图标属于场景，不使用大号矩形按钮。
2. 保留双击空白快捷方式，但不再让它承担唯一入口。
3. 将双击与竖向滑动拆成明确的手势状态：位移未超过阈值才允许双击，进入拖动后立即取消双击候选。
4. 创建操作增加 `idle / pending / success / error` 状态，防止连点并发；数据库异常必须显示用户可见错误。
5. 数据写入成功后先更新可见大纲，再启动树木动画；动画失败不得回滚已经创建的章节。
6. 静态回退、实时 3D 和 3D 尚未 ready 三种状态必须使用同一条创建逻辑。

自动验收：

- 真实点击“新芽 +”后数据库新增 1 行，左侧立即出现新章。
- 连续创建 10 章，标题和排序唯一。
- 退出星球再进入，10 章仍存在并默认聚焦最新章。
- 当前章连续创建 8 节，全部出现在右侧滚动链路。
- 模拟 3D 启动失败时，创建章/节仍成功。
- 真实触控录屏中每次操作都有按下、处理中和完成反馈。

### Task 2：查清并修复目标手机的 3D 启动链路

主要文件：

- `lib/presentation/outline/tree_scene/tree_scene_web.dart`
- `lib/presentation/outline/tree_scene/tree_scene_controller.dart`
- `assets/tree_scene/dist/main.js`
- `tools/tree_scene/src/main.js`
- `tools/tree_scene/src/MagicTreeScene.js`

执行：

1. 新增明确启动状态：iframe 已加载、WebGL2 context 已建立、GLB 已下载、KTX2 已转码、首帧已渲染、Flutter 已收到 ready。
2. 保存并上报完整错误：浏览器 UA、WebGL 版本、renderer、模型 URL、HTTP 状态、KTX2/meshopt 错误和耗时。
3. 8 秒超时不得覆盖真实错误；超时只是一种错误类型，必须记录卡在哪一步。
4. 对 iOS Safari 单独验证 iframe + Flutter CanvasKit 同时占用图形上下文的情况。
5. 若 KTX2 或 meshopt 在目标设备失败，提供同模型的兼容纹理/未压缩几何路径；不能直接退回难看的旧素材。
6. 场景 ready 的定义改为“首帧成功且 Flutter 收到有效标签投影”，不是 JS 构造器完成。

退出条件：三台目标设备均能给出可读启动报告；正常设备进入实时 3D，失败设备明确显示失败阶段，不再静默。

### Task 3：废弃程序树，重建正式美术母版

主要资产：

- `assets/source/magic_tree/blender/magic_tree_master.blend`
- `assets/source/magic_tree/references/树形正视图.png`
- `assets/source/magic_tree/references/树形侧视图.png`
- `assets/source/magic_tree/references/五阶段成长分镜.png`
- `assets/source/magic_tree/references/章节目枝直接承托效果图.png`

禁止继续使用 `build_magic_tree_blender.py` 的正弦曲线批量造树作为正式模型。脚本可保留为技术占位工具，但不能产出生产 GLB。

正式模型要求：

1. 先手工完成成熟古树高模：宽冠、粗壮分叉主干、5 至 7 根可辨识主枝、至少 7 根自然抓地根、真实负空间。
2. 土壤不是球体或圆盘；根、碎土、苔藓和背景地面在材质与接触阴影上连续。
3. 叶片使用阔叶簇，尺寸和朝向有自然变化；不得环形复制成针叶轮廓。
4. 树皮具备粗糙度、法线、空腔、苔藓和局部金色魔法纹理，远近镜头均能读出层次。
5. 章节枝和小节枝与主树共用树皮、叶簇和分叉语言，不能像额外贴上的管子。
6. 木牌、包边、刻字槽和发光纹路均建模并进入同一场景光照。

美术流程：高模定型 -> 正侧背三视审查 -> 低模拓扑 -> UV/PBR -> 五阶段成长形态 -> 骨骼与 Morph -> LOD -> GLB。

美术门禁：成熟树三视图和五阶段正侧图先提交给用户确认。未确认树形前，不进入动画和 Flutter 接入。

### Task 4：重建真实成长系统

目标：完整树苗连续成长为完整古树，而不是缩放、揭开、拼接或换树。

执行：

1. 五个手工形态锚点：树苗、幼树、青年树、成树、古树，每一帧都是完整植株。
2. 主干和根系使用共享拓扑的 Morph；枝条使用曲线弧长生长；叶片按生长点分批萌发与展开。
3. 树高、干径、根幅、冠幅分别使用独立曲线，禁止统一 scale。
4. 0.72 至 1.00 阶段以增粗、增密、根系扩张为主，不再无限增高。
5. 创建章节时，主树在 0 至 120ms 内先产生轻微树液/树皮响应，新章枝再从真实分叉点长出。
6. 创建小节时只改变当前章节枝及其末端叶簇；若早期树龄空间不足，可让主树按规则少量长高，但完成后状态必须持久化，不能一秒后回退。
7. 浏览历史章节只移动相机，不改变树龄、骨骼、Morph 和叶片实例。

动画门禁：60fps 录屏逐帧检查，不得出现枝先动、两段式移动、整体缩放、换模型闪烁和旧枝重新排布。

### Task 5：重建章节枝、小节枝与木牌系统

执行：

1. 章节枝仅从主干向左生长；屏幕最多显示两个章节木牌。
2. 当前章的小节枝仅向右生长；通过右侧滑动切换小节。
3. 新建时枝条从根到梢长出，树皮隆起、叶片展开、木质托架最后成形。
4. 已有枝条使用稳定世界锚点；新增内容不得重新均分整棵树或让旧枝整体位移。
5. 左右滑动只改变相机与可见集合，枝条本身不重新生长。
6. 标签不是 Flutter 矩形卡片；正式 3D 和静态回退都使用同源木牌外观。
7. 长标题在牌面内部受控换行或省略，不允许扩大牌面挤压树形。

退出条件：10 章 × 8 节数据集下，左右信息分区、滑动、创建、重命名、删除、进入小节和灵感拖入全部可用。

### Task 6：重建同源高质量降级路径

静态降级不能再用六张“透明树 + Flutter 矩形标签”。

执行：

1. 从最终批准的同一 Blender 场景、同一相机和同一灯光导出五阶段全屏高 DPR 预渲染。
2. 每个阶段必须按正式手机构图导出，树苗也要占据合理视域，不能只露底部一点。
3. 使用同源枝条、叶簇和木牌预渲染组件，降级标签仍由枝梢承托。
4. 降级只降低阴影、粒子、叶片数量和动态频率，不改变树种、构图和信息架构。
5. 降级模式仍完整支持创建、编辑、删除、左右滑动和进入小节。

退出条件：隐藏“3D/降级”标识后，普通用户不能一眼看出两条路径属于两套 UI。

### Task 7：重新完成手机构图与视觉整合

构图硬要求：

1. 空书：完整小树苗可见，树体占可用高度约 28% 至 38%，保留明确成长空间但不得只露树尖。
2. 成熟树：树与根占可用高度约 78% 至 90%，主干成为首屏视觉中心。
3. 顶栏、卷轴、返回键和速记按钮不得与树冠、木牌重叠。
4. 背景米白、土壤、根系、接触阴影和空气透视连续，无矩形底、透明灰边和贴图分割感。
5. 相机按树龄与焦点章节使用预设轨道，不允许 `BoxFit.contain` 决定最终构图。

每个目标视口均提交：参考图、结果图、50% 叠图和纯轮廓差异图。

### Task 8：把验收标准变成真正的发布阻断

新增统一发布验证命令，至少包含：

1. GLB 结构、纹理、动画、LOD、内存和 draw call 检查。
2. 正视与侧视 silhouette IoU；不再使用“相对自身包围盒宽度”冒充树形匹配。
3. 五阶段完整树轮廓、树高单调、非统一缩放和非揭开检查。
4. 三档视口的参考叠图和布局安全区检查。
5. 创建章、创建节、退出重进、10×8 数据集、3D 启动失败等浏览器集成测试。
6. iPhone Safari、Android Chrome 和 Flutter 原生壳的真实触控录屏。
7. 视觉证据清单缺任一文件，发布验证直接失败。

自动测试只负责阻止明显错误，不能替代肉眼审查。最终发布顺序固定为：

1. 自动门槛全绿。
2. Codex 在真实浏览器和手机视口逐项截图、录屏并自查。
3. 将参考图和结果图并排展示给用户。
4. 用户明确回复“通过”。
5. 才允许打开默认 3D 开关、替换旧生产路径和提交完成报告。

1. `修复大纲页章节与小节创建闭环`
2. `补齐实时3D启动诊断与目标设备兼容路径`

4. `接入真实树龄Morph与连续生长动画`
5. `重建章节枝小节枝与同源木牌系统`
6. `建立同源高质量静态降级路径`
7. `完成手机构图与左右分区交互`
8. `落实视觉回归与真机发布门槛`

每个提交必须独立可运行、带对应测试和证据；不得用一个“大提交”掩盖中间失败状态。

## 六、本轮不做的事情

- 不继续调当前程序树的枝条数量、叶片缩放或相机参数。
- 不把当前六张替身重新放大后继续使用。
- 不用新的 Flutter 卡片样式掩盖缺少真实 3D 木牌的问题。
- 不在没有目标手机启动日志前猜测 Safari 失败原因。
- 不在用户确认树形前继续堆动画代码。
- 不再把“页面不空白”“测试通过”或“能创建数据库记录”称为 UI 完成。

## 七、最终完成定义

只有同时满足以下条件，才可以宣布目标完成：

1. 空书、1 章、2 章、10 章的三档手机截图均与批准效果图处于同一视觉品质。
2. 新建章和节在真实手机上连续 20 次成功，数据、枝条、木牌和动画状态一致。
3. 树苗到古树全程是完整植株的连续生长，没有缩放、揭开、换树或拼接感。
4. 左侧最多两章、右侧当前章小节、左右独立滑动和历史章节相机巡航全部符合定稿交互。
5. 实时 3D 与降级路径均无分割感，且降级不改变信息架构。
6. 性能和恢复测试通过。
7. 用户看到最终并排效果和完整录屏后明确验收通过。
