# 完整实时 3D 魔树全面整改 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用完整实时 3D 魔树替换现有位图帧序列与二维卷须，让同一棵树从幼苗连续成长为参天古树，并让章枝、节枝、标签、镜头和灵感挂靠都存在于统一的三维世界中。

**Architecture:** 保留 Flutter/Riverpod/drift 业务壳，新增 three.js r184 `WebGLRenderer` 场景层；主树使用 GLB 骨骼与形态键，章节枝和小节枝由稳定种子的三维曲线运行时生成，叶片使用实例化渲染。Flutter 通过带 session/sequence 的版本化协议同步大纲快照与单次变更，three.js 只保存可重建的表现状态。

**Tech Stack:** Flutter、Riverpod、WebView/iframe、three.js r184、glTF 2.0/GLB、Blender 4.5 LTS、KTX2/Basis Universal、Meshopt、Node 内置测试、Flutter Test、Playwright 真浏览器验收。

## Global Constraints

- 所有对话、代码注释、文档和提交信息使用中文。
- 正式渲染固定使用 three.js r184 `WebGLRenderer`；WebGPU 只做独立实验，不进入本次关键路径。
- 所有运行资源离线打包；App 无账号、无后端、无网络依赖。
- Flutter 是数据库与业务真相；three.js 不直接修改业务数据。
- 不再修补 28 帧图片，不得使用整图缩放、揭开、切片、羽化、镜像、纵向拉伸或横向裁剪贴图冒充生长。
- 3D 源资产必须包含 `.blend`、源纹理、授权说明、导出脚本和正式 GLB/KTX2，禁止只交付成品模型。
- 每个代码任务按 TDD 执行；先让新增测试失败，再写最小实现。
- 每个任务完成后运行相关测试；每次提交前执行 `C:\Program Files\Git\bin\bash.exe scripts/update_code_map.sh`。
- 3D 任务必须附截图、录屏、canvas 非空检查和性能报告，不能只以“代码运行了”作为完成。
- 不修改数据库表结构；枝形由 `novelId/chapterId/sectionId/sortOrder` 稳定推导。
- 低端回退图必须由最终 3D 模型渲染，禁止继续使用现有仙人掌/藤柱素材。
