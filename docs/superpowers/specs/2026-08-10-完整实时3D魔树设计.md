# 完整实时 3D 魔树设计规格

> 定稿日期：2026-08-10
> 用户决策：不再继续修补 2D 照片、帧序列和卷须贴图，采用完整实时 3D 魔树，目标是做到当前产品能力上限。
> 对应实施计划：`docs/superpowers/plans/2026-08-10-完整实时3D魔树全面整改.md`

## 一、结论

大纲页魔树改为独立的实时 3D 场景：Flutter 继续负责数据库、Riverpod 状态、路由、弹层、输入法、无障碍和业务写入；three.js 场景负责树木、枝条、叶片、土壤、光照、镜头、命中检测和全部生长动画。

当前 `28 张树图 + 2 张卷须 PNG + Flutter 二维坐标布局` 路线整体退役。旧素材只在迁移期间保留为临时回退，正式低端回退图必须由最终 3D 模型重新渲染，不能继续使用现有仙人掌/藤柱素材。

生产渲染器固定为 three.js r184 的 `WebGLRenderer`。不把 `WebGPURenderer` 作为首发生产路线：three.js 官方仍将其描述为实验状态，而本项目必须覆盖 iOS WKWebView 与 Android WebView。WebGPU 只保留为后续独立实验，不阻塞本次交付。

3D 资产使用 glTF 2.0 / GLB，纹理使用 KTX2，网格使用 Meshopt 压缩。three.js 官方 `GLTFLoader` 已原生支持骨骼动画、形态键、KTX2、Meshopt 与 GPU 实例化扩展，符合本项目需求。

## 二、现状审计

### 2.1 可保留能力

- Flutter + Riverpod + drift 的章、节、灵感业务模型。
- `NovelRepository` 的章/节创建、重命名、删除和大纲监听。
- 大纲页双击创建、长按菜单、进入小节页、灵感拖拽挂靠等交互语义。
- 首页已经验证的 `Flutter 壳 + WebView/iframe + three.js + 离线资源` 技术路径。
- `SceneServer` 的回环 HTTP 资源服务思想。
- Web 与移动端分平台包装、场景暂停/恢复、上下文丢失上报、替身图遮挡冷启动的经验。
- 最新章节默认聚焦、小节早期参与树高、成熟后只改变枝叶的业务规则。

### 2.2 必须退役的实现

- `assets/textures/tree_frames/`：28 张 PNG，约 34.67MiB。
- `assets/textures/tree_frames_v3/`：28 张 PNG，约 34.83MiB。
- `assets/textures/tendril_chapter.png` 与 `tendril_section.png`。
- `assets/textures/tree_seg/` 历史切片。
- `magic_tree_model.dart` 中帧号、茎干宽度表、照片矩形和二维卷须布局。
- `outline_page.dart` 中 `_MagicTreeImage`、树帧擦除、黄色扫描线、卷须宽度裁剪和二维枝根压痕。
- `label_layout.dart` 中依赖二维卷须端点的最终标签布局。迁移期可保留给静态回退，正式 3D 标签不再依赖它。
- `scripts/magic_tree_img2img_pipeline.py`、`magic_tree_sd_webui_provider.py`、`validate_magic_tree_frames.py` 的生产用途。文档归档后删除，避免后续继续走错误路线。

### 2.3 根因

当前系统没有“树的三维生长骨架”。树本体是离散图片；章节枝丫是一张横向裁开的固定 PNG；新增章节会重新计算所有二维枝丫坐标。结果必然表现为换图、贴图显露和屏幕坐标移动，无法形成同一个生命体的连续生长。

## 三、目标体验

### 3.1 树木造型

最终树形采用“写实古老生命树”方向，吸收童话魔法树的克制金色生命脉络：

- 从任何阶段都必须一眼看出是树，不能是仙人掌、藤柱、圣诞树锥体或成束麻花藤。
- 成树主干粗壮，根颈外扩，在树高约 30% 处形成第一次主要分叉。
- 5 到 7 根主枝向左右和斜上方舒展，树冠宽度为成树高度的 62% 到 78%。
- 树冠略不对称，有明显负空间，不堆成密实圆锥。
- 树皮是木质裂纹和苔藓，藤蔓只作为局部附生细节，不能构成主干。
- 根系真实扎入土壤，根、土、树干必须是同一光照与接触阴影体系。
- 魔法效果只保留树皮裂隙金绿色微光、嫩芽和少量灵感光点，不使用满屏金色卷纹。

### 3.2 树龄连续变化

树龄由连续参数 `age ∈ [0,1]` 表达，不再映射成 28 张图片：

1. `0.00–0.12`：完整幼苗，有根、细主干、小树冠。
2. `0.12–0.30`：幼树，主干增粗并出现第一次分叉。
3. `0.30–0.55`：青年树，主枝向两侧展开，树冠形成。
4. `0.55–0.78`：成熟树，树高接近封顶，次级枝与叶簇增加。
5. `0.78–1.00`：参天古树，高度变化减弱，主要增加树干厚度、冠幅、枝叶密度和魔法脉络。

每个阶段都是一棵完整的树。禁止把成树整体缩小、从下向上揭开、切片拼接或用纵向缩放冒充生长。

### 3.3 章节与小节

- 一章对应一根真实 3D 章节枝，从主干或主枝的稳定挂点生长。
- 一节对应章节枝上的次级细枝、叶簇或嫩芽，不直接从主干随意伸出。
- `引子`、`第一章`、`第二章`等章级标签只允许出现在屏幕左侧；章枝从树干向左侧展开，标签不得越过屏幕中线。
- 当前章的`第一节`、`第二节`等节级标签只允许出现在屏幕右侧；节枝从当前章枝的次级挂点向右侧展开，标签不得越过屏幕中线。
- 左侧章牌与右侧节签必须有明确层级差：章牌更大、更厚，节签更轻、更小；中央区域只保留树干、枝叶和必要的三维连接关系。
- 新增章节只让新章节枝生长；已有章节枝不能因为重新均分布局而整体换位。
- 新增小节时：树未达到高度封顶前，主树和该章次级枝共同成长；封顶后只增长该章细枝、叶簇和灵感光点。
- 章节删除播放枯萎、回缩和微粒散去，完成后才从场景状态移除。
- 重命名只更新标签纹理，不触发树木重新生长。

### 3.4 新增章节时间轴

统一时间轴总长 950ms：

- `0–120ms`：树皮挂点出现轻微隆起，主树 `age` 开始向目标值过渡。
- `120–680ms`：新枝沿三维曲线从根到梢连续延伸，半径由嫩枝变为稳定枝径。
- `360–760ms`：芽点依次打开，叶片从小到正常尺寸展开。
- `620–900ms`：章节牌从枝端自然展开，文字显现。
- `100–900ms`：如新章节不在当前镜头内，相机与生长同时跟随；禁止生长结束后再单独滑一次。
- `950ms`：场景上报完成，Flutter 结束事务。

主树必须先在视觉上启动，然后新枝开始；不能枝丫先动、树后动。已有枝条随骨骼发生的轻微位移属于自然附着运动，不得表现为整张贴图上下滑动。

### 3.5 浏览章节

- 用户滑动章节时不播放生长动画。
- 树固定在世界坐标中，相机沿预设巡航曲线移动到目标章节。
- 所有枝、叶、牌和光点由同一相机投影，因此不会出现树不动、枝丫在屏幕上独立平移。
- 进入星球后默认定位最新章节；无章节时显示幼苗全景。
- 左半屏纵向滑动只切换章节；右半屏纵向滑动只切换当前章的小节。手指按下时即锁定手势所有者，直到抬起前不得因横向漂移跨区或改变操作对象。
- 章/节标签、写作按钮和返回按钮等直接命中操作优先于区域滑动；未命中控件时才进入左右分区手势。
- 十章或更多章节时，左侧只保留当前章和相邻章的可见标签，相机沿树干巡航并在松手后吸附到目标章；不把所有章节压缩进一屏。
- 当前章有大量小节时，右侧只保留当前小节和相邻小节的可见标签，并围绕当前章枝独立巡航；右侧滑动不得切换章节。
- 一次视野重点展示当前章、相邻章和当前章的小节，但整棵树在远景中仍保持连续，不做二维裁剪窗口。

## 四、3D 资产结构

### 4.1 Blender 源文件

源文件必须保存在：

```text

├── blender/magic_tree_master.blend
├── textures_source/
├── references/

├── licenses/
```

禁止只提交 GLB，不提交 `.blend` 和纹理源文件。

### 4.2 GLB 节点契约

正式模型导出为 `assets/3d/magic_tree/magic_tree.glb`，节点命名固定：

```text
MagicTreeRoot
├── Soil
├── Roots
├── TrunkSkinned
├── CrownGuide
├── MarkerPath_Trunk_00..15
├── MarkerPath_MainA_00..11
├── MarkerPath_MainB_00..11
├── MarkerPath_MainC_00..11
├── LeafPrototype_A
├── LeafPrototype_B
├── BudPrototype
├── ChapterPlaquePrototype
└── SectionTagPrototype
```

动画/形态键命名固定：

```text
tree_age
idle_breath
magic_pulse
wither
age_00
age_20
age_40
age_60
age_80
age_100
```

树干采用骨骼 + 形态键混合：骨骼负责高度、分叉角度和轻微呼吸；形态键负责树干增粗、根颈外扩和树冠轮廓变化。不能只缩放成熟模型的整体骨骼。

### 4.3 章节枝运行时生成

章节枝不是预烘焙到主树模型里的固定数量枝条：

- 由 `CatmullRomCurve3/CurvePath + TubeGeometry` 根据稳定种子生成。
- 稳定种子由 `novelId + chapterId` 产生，同一章每次进入外形一致。
- 根点从 GLB 的主干/主枝 marker path 上采样，不依赖屏幕坐标。
- 生长通过几何 draw range、枝梢芽点和叶片实例共同表达，禁止横向裁剪整张图片。
- 章节枝完成后保持世界变换不变；树龄变化时通过父骨骼/marker path 跟随。
- 小节枝从所属章节枝的曲线采样点生成。

### 4.4 材质与纹理

至少包含：

- 树皮：base color、normal、roughness、AO、emissive mask。
- 叶片：base color + alpha、normal、roughness，使用 `alphaTest`，避免大量透明排序。
- 土壤：base color、normal、roughness、AO。
- 章节牌/小节签：PBR 材质，文字使用高分辨率 `CanvasTexture` 动态生成。
- 环境：512 或 1024 的 KTX2 环境贴图，禁止把大尺寸 HDR 原图直接打进 App。

叶片使用 `InstancedMesh`，不能每片叶子单独一个 draw call。

## 五、场景与 Flutter 边界

### 5.1 Flutter 是唯一业务真相

- drift 数据库与 Riverpod 大纲流保持权威。
- three.js 场景状态是可重建的表现缓存，不直接修改数据库。
- WebGL 上下文丢失或页面恢复后，Flutter 重新发送完整快照，场景必须恢复到一致状态且不重播历史动画。

### 5.2 桥接协议

Flutter → 场景：

```text
scene.init
tree.syncSnapshot
tree.playMutation
tree.focusChapter
tree.setDragPoint
tree.endDrag
tree.setQuality
scene.pause
scene.resume
scene.disposeAssets
```

场景 → Flutter：

```text
scene.ready
scene.contextLost
scene.assetError
scene.telemetry
tree.mutationStarted
tree.branchGrowthStarted
tree.mutationCompleted
tree.hit
tree.requestCreateChapter
tree.requestCreateSection
tree.requestOpenSection
tree.requestEdit
tree.dragTargetChanged
```

每条消息包含 `protocolVersion`、`sceneSessionId` 和单调递增 `sequence`。旧 session 或旧 sequence 的消息必须丢弃，防止数据库流晚到导致动画回弹。

### 5.3 交互所有权

- WebView 内 three.js 处理树木旋转/巡航、射线命中和枝条选择。
- Flutter 的魔毯、速记按钮、弹层始终位于场景之上。
- Flutter 拖拽灵感进入场景时，临时启用全屏拖拽接收层，将归一化坐标以不高于 30Hz 下发给场景；three.js 射线检测后回传目标章/节。
- 数据写入只在 Flutter 收到 drop 后执行。

## 七、性能与质量门槛

### 7.1 画面预算

| 指标 | 高档 | 中档 | 低档 |
|---|---:|---:|---:|
| DPR 上限 | 2.0 | 1.5 | 1.0 |
| 同屏三角形 | ≤ 250k | ≤ 140k | ≤ 70k |
| Draw calls | ≤ 80 | ≤ 55 | ≤ 35 |
| 叶片实例 | ≤ 4,000 | ≤ 2,200 | ≤ 1,000 |
| GPU 纹理预算 | ≤ 96MiB | ≤ 64MiB | ≤ 40MiB |
| 目标帧率 | 60fps | 60fps | ≥30fps |

高档设备交互期间 p95 帧时间 ≤ 20ms；中档 ≤ 24ms；低档 ≤ 33.3ms。新增章节动画不得出现连续 3 帧超过 50ms。

### 7.2 资产预算

- 生产 GLB + KTX2 总打包体积目标 ≤ 18MiB，硬上限 25MiB。
- 首屏必须加载的资产 ≤ 10MiB，其余可在进入页面后分批预热。
- 当前约 69.5MiB 的两套树帧必须在 3D 验收后移除。
- 所有 KTX2 必须带 mipmap 并通过 `ktx validate --gltf-basisu`。
- GLB 必须通过 Khronos glTF Validator，零 error。

### 7.3 视觉验收

- 幼苗、幼树、青年树、成树、古树五个时刻都能一眼看出是完整树。
- 树冠宽而不锥，主枝结构清晰，不能呈圆柱或仙人掌轮廓。
- 新枝从树皮内部长出，有遮挡、接触阴影和材质连续性。
- 新建章节时只有新枝生长，已有枝条不重新排版。
- 浏览章节时由相机移动，不出现屏幕贴图滑动感。
- 章级标签始终只在左侧、节级标签始终只在右侧；任何数量和相机角度下都不得跨越中线或混排。
- 左侧滑动只改变章节，右侧滑动只改变当前章的小节；连续快速滑动、斜向滑动和中线附近抖动均不得串区。
- 树、土壤、背景无抠图边、矩形底、像素分割或颜色接缝。
- 标签处于 3D 空间，有透视、遮挡和明确连接，不像 Flutter 胶囊浮在画面上。

## 八、降级与回退

- `advanced3D=false`、WebGL 不可用、场景连续两次恢复失败时，使用最终 3D 模型预渲染的静态年龄替身。
- 替身包含 6 个树龄档，背景、土壤、构图与 3D 场景一致。
- 低档仍使用实时 3D，只降低 DPR、叶片、阴影、粒子和纹理 LOD；静态替身是最后防线。
- 迁移完成前保留旧 2D 实现于 feature flag 后；3D 真机验收通过后删除旧实现和旧素材，禁止长期双轨维护。

## 九、明确不做

- 不再生成 28 张 AI 树图。
- 不再用照片抠图、切片、羽化、镜像、纵向拉伸、交叉淡化或擦除扫描修树。
- 不用 Rive/Lottie 冒充实时 3D 树。
- 不在 Flutter 每帧重算全部枝丫的屏幕坐标。
- 不在数据库中保存 3D 坐标；枝形由稳定种子与排序可重建。
- 首版不引入物理引擎。枝叶摆动由骨骼、噪声和阻尼实现，避免为非核心功能增加复杂度。

## 十、资料依据

- three.js `GLTFLoader`：支持 glTF 2.0、KTX2、Meshopt、Draco、GPU instancing 等扩展。
- three.js `SkinnedMesh`：支持骨骼蒙皮动画。
- three.js `AnimationMixer`：支持多个动画 clip 的播放、混合和同步。
- three.js `InstancedMesh`：用于大量同材质叶片，降低 draw call。
- Khronos glTF 2.0 与 KTX2：作为跨平台实时 3D 资产与 GPU 压缩纹理标准。
