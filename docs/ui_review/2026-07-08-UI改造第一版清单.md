# UI 改造第一版清单

> 生成日期：2026-07-08  
> 目标读者：Claude 或后续接力开发智能体  
> 范围：当前 App 的三维、二维、动画、材质、交互、性能、验收方式的全面 UI 改造清单。  
> 重要约束：本文件是第一版改造清单，不是最终设计定稿。执行时必须逐项拆小步、逐项截图验收、逐项提交。

## 0. 总判断

当前 UI 已经完成一轮“可用且有风格”的打磨，但它还不是“极致 UI 体验”。现状更接近：

- 首页：Flutter FragmentShader 贴图球 + 星空图片 + 2.5D 环绕文字
- 大纲页：照片魔树背景 + 2D 卷须精灵 + Flutter 布局规则
- 小节页：羊皮纸卡片 + iOS 极简写作界面
- 速记层：羊皮纸底部弹层 + 单悬浮按钮
- 魔毯：素材帧动画 + 全局 Overlay

主要问题不是单个按钮或颜色，而是底层视觉机制不统一：

1. 首页追求真实宇宙，但星球仍是轻量贴图球，无法承载“极致逼真、可缩放、可细看”的目标。
2. 内页追求羊皮纸与魔法书写，但大纲页照片素材、魔毯素材、卡片 UI 的光照、颗粒、比例和动效语言还没有统一规范。
3. 交互动效很多，但缺少统一的镜头系统、手势规则、运动曲线、触觉反馈标准。
4. 资产管线还是一次性脚本和图片拼接，没有形成“高清源图、移动端纹理、预览图、验收图”的完整生产链。
5. 验收主要依赖用户肉眼逐页看，缺少固定截图矩阵、性能预算和视觉回归基线。

第一版改造建议：先做“视觉机制升级”，再做“单页精修”。不要一上来只换图，否则会反复推倒。

## 1. 推荐路线

### 路线 A：继续 Flutter Shader 打磨

适合目标：比现在更漂亮、上线风险低、短期可控。

可做：
- 提高清纹理
- 加法线贴图的伪凹凸
- 加云层、大气、海洋高光
- 做双指缩放的有限范围
- 优化星空和环绕文字

问题：
- 仍不是真 3D 网格
- 放大后细节容易露馅
- 复杂材质和 LOD 很难优雅实现
- 极致真实感上限有限

### 路线 B：Flutter 主体 + 原生/嵌入式 3D 场景

适合目标：保留 Flutter 写作 UI，同时让首页星球达到高真实度。

建议：
- Flutter 继续负责数据、页面、文本、魔毯、卡片、速记
- 首页星球区域升级为独立 3D Scene
- 3D Scene 使用真实球体网格、多材质、LOD、相机、手势
- Flutter UI 作为 Overlay 叠在 3D 场景上

候选方向：
- Flutter + 原生 iOS SceneKit/Metal + Android Filament/OpenGL/Vulkan
- Flutter + Unity as Library
- Flutter + WebView/Three.js 作为技术验证，不建议直接作为最终移动端核心

优点：
- 能支持逼真地球、放大缩小、真实镜头、云层、大气、细节纹理
- 不必重写整 App
- 首页作为核心卖点能上一个档次

风险：
- 双端集成成本高
- 测试和性能调优复杂
- 原生桥接、资源加载、生命周期要单独设计

### 路线 C：整体切到游戏/3D 引擎

适合目标：整个 App 都是高度沉浸 3D 世界。

不建议作为第一版路线。写作、长文本编辑、SQLite、本地语音、弹层、输入法、无障碍都更适合 Flutter 原生 UI。全引擎会把普通写作体验复杂化。

### 推荐结论

采用路线 B：Flutter 保留为 App 主体，首页星球先做 3D 引擎技术验证。若验证结果达不到图 2 级别，再决定是否扩大到更多页面。

## 2. 第一阶段：视觉标准与验收体系

目标：先定义“改到什么算好”，否则后续每项都会靠感觉争论。

### 2.1 建立视觉母题

- [ ] 定义一句总风格：例如“真实宇宙中的私人写作圣物”。
- [ ] 明确两套材质域：
  - 宇宙域：首页星球、星空、轨道、创作能量
  - 书写域：魔树、魔毯、卡片、速记、设置
- [ ] 定义两套材质如何过渡：
  - 首页进入大纲页时，星球缩放/溶解/镜头穿越到书写世界
  - 魔毯作为跨域物件，既可以出现在宇宙页，也可以进入羊皮纸页
- [ ] 禁止每页单独发明风格。

验收：
- 产出 `docs/ui_review/UI视觉母题.md`
- 每页截图能归入“宇宙域”或“书写域”，不能像不同 App 拼起来

### 2.2 建立设计 Token

涉及文件：
- `lib/core/`
- `lib/main.dart`
- 所有 `presentation/*`

清单：
- [ ] 新建全局颜色 Token：宇宙黑、星光蓝、羊皮纸底、墨色、金色、危险红。
- [ ] 新建圆角 Token：小胶囊、卡片、底部弹层、全屏面板。

- [ ] 去除各文件内重复常量，保留局部常量仅用于几何算法。

验收：
- 同一类卡片/弹层/按钮在不同页面观感一致。
- 新增 UI 不需要复制旧页面的颜色值。

## 3. 第二阶段：首页宇宙与三维星球重构

这是最高优先级，因为用户明确提出“非常逼真，甚至可以放大缩小”。

### 3.1 先做 3D 技术验证，不直接替换主线

目标：用最小实验判断路线 B 是否可行。

清单：
- [ ] 建立 `docs/ui_review/3D星球技术验证.md`，记录候选方案。
- [ ] 比较 Flutter shader、Unity as Library、Filament、SceneKit/Metal、Three.js WebView。
- [ ] 每个方案至少评估：
  - 双端支持
  - 包体积
  - 冷启动时间
  - 内存占用
  - 帧率
  - 与 Flutter Overlay 叠加难度
  - 纹理和 LOD 支持
  - 手势相机支持
  - 后续维护成本
- [ ] 先做一个独立 Demo，不接入数据库。
- [ ] Demo 必须支持：自转、拖拽旋转、双指缩放、云层、大气层、海面高光。

验收：
- 在 Android 真机上录屏，能稳定 60fps 或明确标注低端机策略。
- 放大后仍有可见细节，不出现糊成一片。

### 3.2 当前 Flutter 星球短期增强

如果 3D 引擎验证需要时间，可以先增强现有 `PlanetView`。

涉及文件：
- `lib/presentation/home/planet_view.dart`
- `shaders/planet.frag`
- `tool/planet_texture_gen.dart`
- `assets/textures/*.jpg`

清单：
- [ ] 支持更高分辨率纹理，至少 4096x2048，视设备降级。
- [ ] 引入 normal map 或 height map，先做 shader 伪凹凸。
- [ ] 引入云层纹理，云层与地表不同转速。
- [ ] 引入夜光图，夜半球可见城市灯光。
- [ ] 加真实大气边缘：蓝色散射不是简单 rim，而是随视角和光照变化。
- [ ] 改善海洋：高光、粗糙度、颜色深浅、浅海岸线。
- [ ] 支持有限双指缩放，缩放时环绕文字和标题自动退让。

验收：
- 图 1 中地球不再像“圆形图片贴上去”，至少有云、大气、海面反光、地形暗示。
- 缩放到 1.5x 时不明显糊。

### 3.3 真 3D 星球目标规格

如果选择路线 B，目标不是“更高清图片”，而是完整 3D 机制。

清单：
- [ ] 球体网格：真实 sphere mesh，可调细分。
- [ ] 材质层：
  - 地表 albedo
  - normal map
  - roughness map
  - ocean specular mask
  - cloud layer
  - atmosphere shell
  - night lights
- [ ] LOD：
  - 远景低清
  - 常规 2K/4K
  - 放大时局部高清或分区纹理
- [ ] 相机：
  - 拖拽旋转
  - 双指缩放
  - 惯性
  - 回弹边界
  - 点击星球进入大纲页时镜头推进
- [ ] 性能：
  - 首页静置时低功耗
  - 滑动 PageView 时暂停不可见星球渲染
  - 后台暂停 3D 渲染

验收：
- 可录制 10 秒星球近景，地表、云层、大气有层次。
- 快速缩放和旋转不掉帧到明显卡顿。

### 3.4 首页 UI 重排

涉及文件：
- `lib/presentation/home/home_page.dart`
- `lib/presentation/home/orbiting_inspirations.dart`
- `lib/presentation/home/starfield.dart`
- `lib/presentation/settings/settings_page.dart`

清单：
- [ ] 重新确定首页层级：星空底、星球主视觉、环绕灵感、标题、设置、魔毯、速记。
- [ ] “Create Something” 不应像普通文字漂在中间，要变成品牌级入口。
- [ ] 星球标题、书名、设置、魔毯不能互相抢视觉。
- [ ] 支持星球放大时隐藏或淡出环绕文字。
- [ ] 环绕灵感从简单椭圆运动升级为更自然的轨道：
  - 远处更小更虚
  - 近处避开星球中心主体
  - 可被星球真实遮挡
  - 长文本有节奏地淡出，不硬截断在画面边缘
- [ ] 星球多本书切换时，PageView 可以保留，但 3D 场景要有预加载与暂停策略。

验收：
- 首页第一屏只有一个绝对视觉中心。
- 任何一个浮层都不能遮住星球的关键区域。

## 4. 第三阶段：大纲页魔树重构

当前大纲页已经复杂，改造重点不是重新发明，而是统一美术、降低脆弱性、增强空间感。

涉及文件：
- `lib/presentation/outline/outline_page.dart`
- `lib/presentation/outline/magic_tree_model.dart`
- `lib/presentation/outline/label_layout.dart`
- `assets/textures/magic_tree_*.jpg`
- `assets/textures/tendril_*.png`

### 4.1 魔树视觉目标

清单：
- [ ] 决定魔树是“真实摄影风”还是“手绘铅笔风”。当前 AGENTS 和旧规格仍写铅笔树，但实现已经是魔树照片素材，需同步设计目标。
- [ ] 若保留魔树摄影风，所有枝丫、标签、灵感小卡都要服从同一光照方向。
- [ ] 章节与小节卷须需要更自然地长在树干上，减少“贴图贴上去”的感觉。
- [ ] 树龄阶段从 3 张图扩展为更连续的过渡，避免阶段切换突兀。
- [ ] 章/节标签从纯胶囊升级为“贴在枝端的纸签”或“浮在枝端的魔法墨签”，和世界观更统一。

验收：
- 新增章节时，用户能感到“树长出来”，不是 UI 元素出现。

### 4.2 魔树布局机制

清单：
- [ ] 给 `magic_tree_model.dart` 增加可视化调试模式，显示章带、小节带、裁剪线、禁区。
- [ ] 窗口模式目前规则多且脆弱，需写成可审查的布局策略文档。
- [ ] 为窄屏、宽屏、小字、大字、极多章节建立布局边界。
- [ ] 右下速记按钮、右上魔毯、树枝标签的避让规则要统一到一个安全区域系统。
- [ ] 拖拽磁吸目标要有更强视觉提示，不只靠标签变金。

验收：
- 1 章 20 节、10 章每章 5 节、长标题、多灵感预览都不重叠。

### 4.3 大纲页动效

清单：
- [ ] 章枝生长、节枝生长、树龄切换、镜头滚动使用统一曲线。
- [ ] 加节时镜头自动跟随到新节，且不过度跳。
- [ ] 删除章/节时不要瞬间消失，可用枯萎/剪断/淡出。
- [ ] 拖拽灵感落到章/节时，应有“吸入枝端”的终态动画。

验收：
- 新增、删除、拖入、重排都能录屏解释清楚，不靠 Toast 补说明。

## 5. 第四阶段：灵感魔毯重构

涉及文件：
- `lib/presentation/outline/magic_carpet.dart`
- `lib/core/carpet_constants.dart`
- `assets/textures/carpet_*.png`

### 5.1 魔毯视觉目标

清单：
- [ ] 明确魔毯是“真实飞毯物件”，不是普通列表容器。
- [ ] 当前 560x560 帧素材适合常规展开，不适合高倍放大，需准备更高清源帧。
- [ ] 缩球态、展开态、拖拽态、回收态需要统一的物理逻辑。
- [ ] 魔毯列表不应像普通 ReorderableListView，卡片应像压在毯面或浮在毯上的纸条。
- [ ] 魔毯右上角全局存在时，要定义在每个页面的避让策略。

验收：
- 魔毯展开时既像一个物件，又能清楚管理灵感。

### 5.2 魔毯交互

清单：
- [ ] 展开、收起、缩边栏、临时露出完整球的状态机写成文档。
- [ ] 拖拽时垃圾桶、树磁吸、小节页落点、拖回魔毯之间不能互相抢事件。
- [ ] 卡片排序把手和长按拖出要减少冲突。
- [ ] 魔毯滚动吸附卡槽的逻辑要覆盖惯性、轻点打断、重排后回弹。
- [ ] 删除灵感必须有强危险反馈，和普通放回魔毯区分。

验收：
- 用户可以盲测完成：新建灵感、排序、拖到章、拖到节、拖回魔毯、永久删除。

## 6. 第五阶段：小节写作页重构

涉及文件：
- `lib/presentation/section/section_page.dart`
- `lib/presentation/section/inspiration_card.dart`
- `lib/presentation/section/card_deck_sheet.dart`
- `lib/presentation/section/card_editor_page.dart`

### 6.1 写作体验目标

清单：
- [ ] 小节页应从“卡片展示”升级为“写作工作台”。
- [ ] 当前主区只有一张卡，适合简洁，但缺少写作上下文和章节进度感。
- [ ] 明确卡片与正文的关系：卡片是灵感片段、段落草稿，还是可写完整小说正文。
- [ ] 长文编辑器需要更像沉浸写作页，弱化工具感。
- [ ] 提供字数、保存状态、最近修改时间等轻量反馈，但不要变成办公软件。

验收：
- 用户进入小节页后知道自己是在“写小说”，不是只在管理便签。

### 6.2 卡片包与编辑器

清单：
- [ ] 卡片包展开从普通 bottom sheet 升级为更强的卡组空间感。
- [ ] 重排、打开、拖回魔毯需要有不同手势和视觉暗示。
- [ ] 长文本编辑器支持极长文本时，要保留光标、滚动、键盘弹起体验。
- [ ] 自动保存要有轻反馈，例如“已保存”墨迹淡出。
- [ ] 删除/放回魔毯路径要避免误触。

验收：
- 6 万字文本继续稳定。
- 键盘弹出时不挡住最后几行。

- `lib/presentation/shared/quick_capture/voice_capture_sheet.dart`

清单：

- [ ] 当前按钮是黑色 Material 圆形，和高端宇宙/羊皮纸系统都略断层，应重做为定制物件。

## 8. 第七阶段：素材与资产管线

当前资产状态：

- 星球纹理：`assets/textures/*.jpg` 为 2048x1024
- 星空背景：941x1672
- 魔树：941x1672
- 魔毯帧：560x560
- 卷须精灵：130x106

如果目标是极致 UI，这些尺寸只适合当前手机展示，不足以支撑放大细看。

清单：
