# UI 改造第一版清单：极致 3D 与动画重构版

> 生成日期：2026-07-08  
> 目标读者：Claude 或后续接力开发智能体  
> 用户目标：不是继续微调当前 UI，而是对当前 App 所有 UI 做全面大改造，目标达到极致 3D 效果、极致动画效果、极致沉浸体验。  
> 执行原则：任何任务如果只是“换图片、调尺寸、改颜色、加一点阴影”，都不算完成。本轮改造的核心是重建 UI 表现机制。

## 0. 结论先行

当前 App 的 UI 已经能用，也有明确的魔法写作气质，但它不是用户现在想要的目标。用户现在要的是：

- 首页三维星球达到产品核心卖点级别，接近高质量 3D 资产，而不是 2D 贴图球。
- 大纲页不再只是照片背景 + 2D 卷须，而是有空间深度、镜头、真实生长动画的 3D 魔法树场景。
- 灵感魔毯不再只是帧动画图片，而是有 3D 物体感、布料感、飞行动效、空间投影和真实拖拽反馈的全局魔法容器。
- 小节页不再只是羊皮纸卡片，而是有 3D 卡堆、空间层叠、打开/收起/重排动画的沉浸写作工作台。
- 速记按钮和弹层不再只是普通浮层，而是具有魔法物件感、声波/墨迹/粒子反馈的全局交互系统。
- 所有页面都要以镜头、空间、光照、材质、粒子、物理动效为核心组织，而不是传统 Flutter 平面控件堆叠。

因此，后续 Claude 执行时必须按“全 UI 视觉机制重构”理解本清单。

## 1. 总体技术方向

### 1.1 当前技术不足

当前核心表现方式：

- 星球：`FragmentShader` 在 Flutter 画布中模拟球面贴图。
- 星空：静态图片按能量档位切换。
- 环绕文字：Flutter 2.5D 平面变换。
- 魔树：照片素材 + 2D 卷须精灵 + 几何布局算法。
- 魔毯：PNG 帧动画 + Flutter Overlay。
- 卡片：Flutter Container + 阴影。
- 速记：普通悬浮按钮 + bottom sheet。

这些机制适合“轻量、稳定、快速开发”，但无法满足“极致 3D 和动画体验”。问题不是某个参数没调好，而是表现机制不够。

### 1.2 新技术目标

必须升级为“Flutter 应用壳 + 实时 3D/高级动画表现层”的架构：

- Flutter 继续负责：
  - 数据库
  - Riverpod 状态
  - 长文本编辑
  - 输入法
  - 系统语音
  - 路由和业务逻辑
- 3D/动画表现层负责：
  - 首页星球
  - 星空/粒子
  - 大纲魔树
  - 魔毯
  - 卡片堆空间动画
  - 页面转场
  - 高级材质、光照、阴影、镜头

### 1.3 候选技术路线

Claude 必须先做技术验证，但方向不是“是否要做 3D”，而是“用哪套 3D 方案做得最好”。

候选：

1. Flutter + Unity as Library
   - 适合：最高沉浸、完整 3D 场景、成熟动画/粒子/材质/相机。
   - 风险：包体积、双端集成、Flutter 与 Unity 事件桥接复杂。

2. Flutter + Filament
   - 适合：PBR 渲染、高性能移动端 3D、轻于 Unity。
   - 风险：Flutter 插件/原生桥接需要较多底层工作。

3. Flutter + 原生 iOS SceneKit/Metal + Android OpenGL/Vulkan/Filament
   - 适合：双端分别做到高质量。
   - 风险：两套原生实现维护成本高。

4. Flutter + WebView/Three.js
   - 适合：快速验证 3D 设计。
   - 风险：最终 App 体验、手势、性能、离线资源和系统集成不够稳。

禁止把当前 `planet.frag` 继续打磨当成最终路线。它可以作为临时过渡，但不能作为极致 3D 的终点。

## 2. 极致 UI 总体标准

后续每个页面都必须满足以下标准。

### 2.1 视觉标准

- [ ] 有明确空间层次：前景、中景、背景、景深关系清晰。
- [ ] 有真实或拟真的光照方向：阴影、高光、边缘光不能互相矛盾。
- [ ] 核心物件使用 3D 或伪 3D 表现：星球、魔树、魔毯、卡片堆、速记按钮都必须有体积感。
- [ ] 有材质区分：金属、纸张、布料、树皮、海洋、云层、星尘各有不同反射/粗糙度/纹理。
- [ ] 有动态反馈：重要物件不能死静态，必须有呼吸、漂浮、自转、生长、粒子或微动。
- [ ] 页面不是控件拼贴，而是一个小场景。

### 2.2 动画标准

- [ ] 每个核心操作都有开始、过程、结束三段反馈。
- [ ] 动画不能只是淡入淡出，必须有空间运动或材质变化。
- [ ] 页面转场必须有镜头感。
- [ ] 拖拽必须有吸附、磁场、落点、入池/出池的终态动画。
- [ ] 删除必须有危险感和不可逆感。
- [ ] 新建必须有诞生感。
- [ ] 保存必须有轻反馈。

### 2.3 性能标准

- [ ] 真机 profile 模式验收，不以 debug 截图为准。
- [ ] 首页 3D 动态目标 60fps；低端机允许降级但不允许卡顿。
- [ ] 大纲页复杂章节场景保持滑动流畅。
- [ ] 魔毯 100 条灵感仍能展开、滚动、拖拽。
- [ ] 小节页 6 万字文本仍能稳定编辑。
- [ ] 所有不可见动画必须暂停。

### 4.1 三维星球

目标：图 2 级别的高细节地球，并支持缩放观察。

清单：

- [ ] 用真实 3D 球体替代 Flutter shader 圆球。
- [ ] 支持多层材质：
  - 地表颜色
  - 法线凹凸
  - 海洋反射
  - 云层
  - 大气

### 4.2 星空背景

目标：从静态背景图升级为动态宇宙空间。

清单：

- [ ] 使用粒子星场或 3D 星空盒。
- [ ] 星云有缓慢流动。
- [ ] 创作能量越高，星光更密、更亮，但不刺眼。
- [ ] PageView 切换星球时，星空有视差。
- [ ] 空宇宙时星空冷寂，创建第一本小说时有点亮仪式。

验收：

- 录屏能看到星空不是静态图。
- 不同创作量的宇宙状态一眼可分辨。

### 4.3 环绕灵感

目标：从 Flutter 文本绕圈，升级为真实空间轨道信息流。

清单：

- [ ] 灵感文字成为 3D 场景中的轨道标签或光带。
- [ ] 文字在星球背面被真实遮挡。
- [ ] 文字靠近镜头时清晰，远离时淡出。
- [ ] 超长文字不硬截断，改为轨道中逐字隐入星尘。
- [ ] 拖动星球时，轨道随空间变化。
- [ ] 点某条环绕灵感可以展开预览，但不破坏主视觉。

验收：

- 环绕灵感不再像贴在屏幕上的字幕。

### 4.4 首页控件重排

清单：

- [ ] `Create Something` 改成品牌级 3D/光效标题，不再只是白色斜体文字。
- [ ] 设置按钮重做为星图仪或金属小齿轮，保留清晰点击区域。
- [ ] 书名成为星球铭牌或轨道铭牌。
- [ ] 创建小说时：星尘聚合成新星球，不是只弹窗建记录。
- [ ] 删除小说时：星球暗淡、碎散或坠入远处，不是普通确认后消失。

验收：

- 新建/删除/切换小说都像宇宙事件。

### 5.1 3D 魔树场景

清单：

- [ ] 魔树从静态照片升级为 3D 或多层伪 3D 场景。
- [ ] 树干有体积、法线、阴影。
- [ ] 章节枝条沿树干真实生长。
- [ ] 小节枝条从章枝上生长，不只是固定精灵贴图。

清单：

- [ ] 灵感拖到章/节后，变成枝端小光点、纸片、果实或星尘。
- [ ] 小节下最多 3 条预览可以改为空间化灵感叶片。
- [ ] 灵感数量越多，该枝条越亮或越繁茂。
- [ ] 拖拽落点有磁场线、吸附音效/触觉、落入动画。

验收：

- 用户能从树的视觉状态感知哪里有灵感。
